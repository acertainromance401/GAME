2026-11-08 승인 브랜딩은 **B안 앱 아이콘**, 공통 워드마크, 정적 시작 화면과 기존 복싱 오프닝, 메인·스토리 단체 아트·이용권 대표 아트·체육관 헤더와 선택형 연습 안내에 적용했습니다. 실제 모델의 텍스트 없는 이미지 레이어를 사용하고 이름·진행·가격은 실제 다국어 UI로 표시합니다. 현재 워드마크는 밝은 색·적색 계열을 사용하며 먹색은 시안의 색상 옵션입니다. 메인의 라이브 캐릭터·기존 카메라·개별 하단 버튼과 기존 버튼 배치, 실전 해설·전투 규칙·맵·오프닝 안무를 유지합니다. 연습 안내는 직접 열 때만 나타나며 안내 중에는 홀드 입력을 해제하고 원래 버튼을 구성에서 제외합니다. 원래 장면·컨트롤러는 유지하고 닫을 때 버튼을 복원하며 안내 중 연습 시간을 집계하지 않도록 연결했습니다.

최종 서명된 iPhone SDK 빌드와 단일 실행의 집중 단위 3개·기본 설정 UI 3개가 통과했습니다. 한·영·일 안내의 실제 적색 로고 픽셀과 복귀 후 JAB·종료 버튼의 동일 프레임을 검사하고 실제 시뮬레이터 캡처 19장을 정리했습니다. 실제 iPhone은 사용 불가 상태여서 이번 앱은 설치하지 못했으며 실기기 화면·터치·햅틱·플레이 체감과 연습 시간 제외량은 직접 확인하지 않았습니다. 작은 화면·큰 글씨·VoiceOver·동작 줄이기 및 전체 전투/AI·실결제·실계정 검사는 이번 범위에서 실행하지 않았습니다. 구현과 최종 근거는 [브랜딩 적용 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#19-승인-브랜딩의-앱-적용)을 따릅니다. App Store 배포 준비는 사용자 요청으로 중단 상태이며 브랜딩 승인으로 재개하지 않습니다.

전면 디자인 교체의 방향과 실제 진행 상태는 [UI/UX 전면 재설계 제안](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md)에 기록합니다. 승인된 메인·스토리 선택·라커룸·실전 HUD·코너/결과와 보조 화면의 네이티브 UI 구현을 완료했습니다. 전투 조작 버튼은 왼쪽 3×3·오른쪽 백스텝/공격 구성을 유지하며, 후속 요청으로 두 묶음을 양끝 쪽으로 옮겼습니다. 메인 하단의 넓은 배경 바도 제거해 기존 라이브 복서의 전신이 드러나도록 했습니다. 이 UI 작업은 캐릭터·맵·복장 디자인, 게임 장면·컷씬과 기존 포즈·모션·카메라·조명·전투 동작을 변경하지 않습니다. 기존 실제 캐릭터 모델의 독립 UI용 렌더와 원본 게임 장면의 변경은 구분합니다. 동시에 들어온 별도의 모델 소스 변경은 아래 실전 적용 기록에서 구분합니다.

2026-11-08에는 실제 모델의 다섯 화면 한·영·일 시안·프로토타입·14초 시연을 제작하고, 승인 이후 중앙 라이브 복서·상단 랭킹·하단 탐색의 메인과 단체 샷·가로 대진표의 스토리 선택을 앱에 적용했습니다. 기존 Game Center 진입·진행·이용권·복장 미리보기·준비 취소를 유지합니다. 공통 제목·버튼의 굵기와 코너 문구를 다듬었으며 RIVAL을 가격 등급으로 표현하지 않습니다. 최종 단위 11개·세 언어 메인 UI 1개와 실기기 UI 3개, 서명된 iPhone SDK 빌드가 통과했습니다. 프로토타입 144개 조합도 재검사했습니다. 초기 확장 시뮬레이터 검사에는 오디오 해제 시간 초과 실패 1개가 있었으며 단독 재실행·실기기 검사는 통과했습니다. 실기기 자동 터치·캡처와 사람의 햅틱·플레이 체감은 구분합니다. 현재 스토리 상대 7개 정의는 아래 10월의 5명 제출 기록을 소급 변경하지 않습니다. 상세 범위는 [첫 네이티브 적용 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#12-승인-이후-첫-네이티브-적용-메인스토리-선택)을 따릅니다.

같은 날 후속 라커룸·경기 준비도 종이색 표면, 기존 라이브 선수와 스타일·복장·자세·스토리 네 탭으로 교체했습니다. 원본 모델의 복장 12개·스타일 3개 견본을 사용하며 기존 카메라·조명·포즈·회전은 유지합니다. 소유 장비는 즉시 착용하고 잠긴 장비는 미리보기만 하며, `준비 완료`는 새 확정 절차가 아닌 닫기입니다. 최대 글씨에서는 한 열 목록과 개별 요구 조건을 우선합니다. 최종 단위 13개·넓은 시뮬레이터 UI 3개와 별도 iPhone 12 mini 최대 글씨 UI 1개, 서명된 iPhone SDK 빌드가 통과했습니다. 각 UI 검사는 세 언어를 실행합니다. 일반 크기·준비 취소는 한·영·일 실기기에서 통과했지만, 최종 최대 글씨 실기기 검사는 자동화 모드 초기화 시간 초과로 실행되지 못했습니다. 최종 앱은 사용자 데이터를 지우지 않고 실기기에 설치·정상 실행했습니다. 세부 범위와 한계는 [라커룸 적용 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#13-후속-네이티브-적용-라커룸경기-준비)에 구분합니다.

같은 날 실전 HUD를 양측의 얇은 상태 바와 중앙 시계로 정리하고 조작 버튼의 무광 표면·색·테두리를 교체했습니다. 왼쪽 3×3 패드와 오른쪽 백스텝·잽/크로스의 위치·순서·크기·간격 및 터치다운·홀드·해제는 그대로입니다. 최종 단위 10개·기본 설정 UI 3개와 서명된 iPhone SDK 빌드가 통과했습니다. 한·영·일 실제 버튼 좌표와 아이콘 픽셀, 입장·KO·다음 라운드를 검사했으며 작은 화면·큰 글씨·VoiceOver·동작 줄이기 검사는 사용자 요청으로 제외했습니다. 최종 앱은 13:00 KST에 iPhone에 설치했지만 마지막 실행은 기기 잠금으로 차단돼 수정본의 실기기 화면·터치감·햅틱은 미확인입니다. 앞서 선택한 기존 위빙 고정 수치·인트로 건너뛰기 검사의 실패와 별도로 들어온 사우스포 눈 모델 변경은 [실전 적용 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#14-후속-네이티브-적용-실전-hud버튼-외형-기존-배치-유지)에 구분합니다.

이후 남은 코너·결과·설정·새 경기 확인·코너 노트·랭킹·스토리 안내와 체육관 헤더까지 종이색 기록·준비 공간으로 마무리했습니다. 실제 회피·공격 기록과 코너 보고를 사용하고, 플레이 이력이 없는 기본 잽을 반복 습관처럼 표시하던 행은 제외했습니다. 기록 행을 첫 화면에서 읽을 수 있게 배치하며 기존 대기·공개·재도전·탐색·거래 동작과 전투 버튼 배치는 유지합니다. 집중 단위 10개·기본 설정 UI 7개가 최종 관련 실행에서 통과했고, 최종 서명된 iPhone SDK 빌드도 통과했습니다. 마지막 앱은 **13:55 KST에 사용자 데이터를 지우지 않고 실제 iPhone에 설치·정상 실행했습니다.** 작은 화면·큰 글씨·VoiceOver·동작 줄이기 검사는 계속 제외했습니다. 실제 앱 실행과 사람의 화면·눌림감·햅틱·장기 플레이 관찰은 구분하며, 실거래·전체 회귀·배포 검증을 뜻하지 않습니다. 중간 빌드·설정 검사 실패와 수정, 14개 보호 소스의 동일 해시 및 기존 갤러리·오프라인 패키지에 추가한 네이티브 캡처 21장은 [잔여 UI 적용 완료 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#15-잔여-네이티브-적용-완료-코너결과와-보조-화면)에 구분합니다.

사용자의 후속 요청으로 일반·스토리 경기의 기존 해설 문구를 상단 HUD 아래 **최대 500pt 너비·20pt 높이의 한 줄**로 복구했습니다. 시그니처·카운터와 같은 공간을 번갈아 사용하고 연출·일시 정지·설정·KO·코너·결과에서는 해설을 숨깁니다. 실제 보이는 캐릭터 메시의 근·원거리/8개 공격 투영에서 **8pt 여유**를 검사했고, 최종 단위 5개·기본 설정 UI 3개와 서명된 iPhone SDK 빌드가 통과했습니다. UI에서는 한·영·일 해설 갱신·기존 버튼 좌표·아이콘과 설정·KO·다음 라운드·스토리 인트로/재도전 흐름을 확인했습니다. 최종 앱은 **14:26 KST에 실제 iPhone에 설치했지만 실행은 기기 잠금으로 차단됐습니다.** 사용자 데이터·조작 배치·게임 장면·전투 규칙은 유지하며, 실기기 화면·햅틱 체감과 제외된 네 가지 검사는 수행하지 않았습니다. 기존 카운터 피해 문구·중간 검사 수정과 최종 실제 캡처는 [해설 복구 기록](../docs/product/RIVAL_UI_UX_FULL_REDESIGN_PROPOSAL.md#16-후속-요청-실전-해설-복구)에 구분합니다.

`legacy/python/pixel_boxing/pixel_boxing_topdown.py`와 `boxing_core.py`를 기준으로 만든 네이티브 iPhone 가로 화면 버전입니다. iOS는 Tkinter와 Python `.py` 창을 직접 앱 번들로 실행할 수 없으므로, 동일 저장소 안에서 전투 규칙과 행동 패턴 AI를 Swift로 이식하고 화면은 SceneKit 기반 실제 3D 씬으로 재구성했습니다.

## 터치 공격 조합

| 홀드 입력 | JAB | CROSS |
| --- | --- | --- |
| 없음 | 잽 | 크로스 |
| 중앙 가드 | 왼쪽 어퍼컷 | 오른쪽 어퍼컷 |
| L 더킹 | 왼쪽 바디 | 오른쪽 훅 |
| R 더킹 | 왼쪽 훅 | 오른쪽 바디 |

이 조합은 데스크톱 버전의 `W/Q/E + A/D` 입력 규칙과 같습니다. 가드는 이동 패드 중앙,
더킹은 양옆 아래에 유지하며 공격 버튼에는 선택된 조합명이 표시됩니다. 공격은 터치
시작에 한 번 입력됩니다. 겹쳐 누른 더킹을 놓으면 아직 누르고 있는 방향으로 복귀합니다.

JAB/CROSS 버튼 위의 `BACKSTEP`은 기본 비용 31에 스타일 배율을 적용해 상대 반대 방향으로
0.22초 동작 중 0.18초에 걸쳐 최대 34만큼 이동하며, 0.035–0.18초에 회피가 적용됩니다. 인파이터·슬러거의 비용은 31,
아웃복싱은 18.6입니다. 필요한 비용보다 스태미나가 적거나 공격·피격 경직·탈진 중이면 사용할 수 없습니다.

### 위빙과 훅

- 이동 패드 왼쪽 위의 **L 위빙 → JAB**은 왼훅, 오른쪽 위의 **R 위빙 → CROSS**는 오른훅입니다.
  기존 더킹 조합과 버튼 크기·배치는 유지합니다. 위빙은 한 번 누르면 한 번만 실행되며 홀드 자동반복은 없습니다.
- 실전 비용 9, 동작 0.36초, 재시작 대기 총 0.48초입니다. 회피 진입부터 0.23초까지 최대 12 게임 단위
  측면 이동하며 링·상대 충돌 경계를 따릅니다. 체육관에서 위빙·연계 훅도 연습할 수 있습니다.
- 머리 공격을 맞는 방향에서 충분히 숙인 뒤 0.27초 전까지 피합니다. 바디·잘못된 방향·공격 중에는
  위빙 회피가 적용되지 않습니다. 별도 무적이나 위빙 전용 피해 보너스는 없으며,
  실제 회피 성공은 더킹과 같은 등급·카운터·상위 등급 RIVAL MOMENT 경로를 사용합니다.
- 같은 쪽 공격을 미리 누르면 0.23초 이후 훅으로 이어지고, 종료 후 0.12초까지 입력 유예가 있습니다.
  피격·탈진·일시정지·화면 이탈·라운드 종료는 예약을 취소합니다. 훅 자체는 기존 비용·피해·판정 시간을 씁니다.
- 더킹은 무릎·고관절 하강과 방향성 몸통 회전, 전방 숙임을 연결하며 장갑은 실제 턱을 따라갑니다.
  머리 훅·어퍼컷은 낮은 진입에서 다리와 골반이 먼저 펴지고 상체 숙임이 풀린 뒤 장갑이 도착합니다.
  더킹을 계속 누르면 회수 뒤 다시 그 낮은 방어 자세로 돌아갑니다. 바디샷은 낮게 준비해 복부로 상승하는 짧은 어퍼컷 궤적입니다.

## 공격 데미지와 가드 비용

| 기술 | 기본 체력 데미지 | 가드 체력 데미지 | 가드 스태미나 소모 | 기본 사거리 |
| --- | ---: | ---: | ---: | ---: |
| 잽 | 6 | 2 | 5.4 | 44 |
| 크로스 | 11 | 4 | 9.9 | 38 |
| 왼쪽 바디 | 9 | 4 | 8.1 | 29 |
| 오른쪽 바디 | 10 | 4 | 9.0 | 30 |
| 왼쪽 훅 | 11 | 4 | 9.9 | 26 |
| 오른쪽 훅 | 12 | 5 | 10.8 | 27 |
| 왼쪽 어퍼컷 | 13 | 5 | 11.7 | 25 |
| 오른쪽 어퍼컷 | 14 | 6 | 12.6 | 26 |

표의 피해와 가드 비용은 스타일·카운터·반복 공격 보정 전 기준값입니다. 가드 체력
데미지는 기본 데미지의 40%를 반올림하며 최소 1입니다. 가드 스태미나 소모는 기본
데미지의 90%에 방어자 가드 스태미나 배율을 곱하고 최소 5를 적용합니다. 가드 HP 피해에는
공격자 피해·반복·노출 보정과 방어자 가드 HP 배율이 적용되지만, 가드 스태미나 피해에는
공격자 피해·반복·노출 보정이 적용되지 않습니다.
일반 가드 중에는 스태미나가 회복되지 않고, 스태미나가 0이 되면 가드가 깨지면서 탈진과 노출이
발생합니다. 헛스윙 노출 상태에서 맞으면 피해가 1.4배가 되며 바디와 훅은 추가로 1.2배가
적용됩니다. 같은 기술을 세 번째부터 반복하면 피해에 0.85배를 누적 적용하고 최저 50%까지 내려갑니다.
스토리 강타형의 회복 단계만 최대 2초 가드·초당 6 회복을 사용하며, 이후 가드 없이
초당 16.5로 목표 45까지 회복합니다. 플레이어·다른 상대의 일반 가드 규칙과 구분합니다.

기본 사거리는 게임 단위의 선수 중심→장갑 중심 거리입니다. 실제 선수 중심 간 적중 한계는
`기본 사거리 × 스타일 리치 배율 + 14 + 0.34 / 0.025`입니다. 추가 14는 모든 공격에 공통인
리치 확장이며, 표면 반경 0.34는 렌더링 단위에서 게임 단위 13.6으로 환산합니다.
이 값은 거리 후보 한계이며, 활성 구간의 실제 공유 포즈·장갑 궤적 접촉도 필요합니다.
공격 방향·조준점은 시작 때 고정하고 접촉 시각의 방어 상태를 적용합니다.
스타일별 배율과 체육관 샌드백 판정은 [게임 가이드](../docs/product/GAME_GUIDE.md#26-8종-공격의-실제-전투-수치)를 따릅니다.

## 라운드 판정과 AI 난이도

- 제한시간 종료 시 플레이어 HP가 더 높으면 승리, 더 낮으면 패배입니다.
- 양쪽 HP가 정확히 같으면 무승부입니다.
- 플레이어가 승리했을 때만 라운드 숫자가 증가합니다. 관측 표본 기반 적응 계수와 별도로
  라운드별 숙련도가 판단 간격·습관 대응·풋워크·짧은 연계에 반영됩니다. 체력·피해·사거리는 유지합니다.
- 무승부와 패배 후에는 같은 라운드 숫자로 재경기합니다.
- 승패와 무관하게 모든 완료 라운드의 습관을 장기 프로필에 병합합니다.
- 전술 읽기는 이전 완료 라운드의 확정 습관에서 정하고 결과에서 코너 리포트를 제공합니다.
- 사거리·스태미나 조건으로 행동 후보를 걸러내고 읽기에 맞는 목표 거리로 계속 이동합니다.
  현재 거리·스태미나·보이는 공격에는 고정 규칙으로 반응하지만 경기 중 수집한 통계로 학습 정책을 재평가하지 않습니다.

## 메뉴·스토리·대기실 인터랙션 개선 (2026-11-07)

- 공용 메뉴 버튼과 일반 선택 버튼은 120ms 눌림 피드백을 사용합니다. 일반 환경에서는 0.98배 축소와 투명도 변화를, 동작 줄이기에서는 투명도 변화만 사용합니다. 비활성 버튼에는 눌림 효과를 적용하지 않습니다. 공용 메뉴 버튼 스타일의 주요 행동은 최소 48pt, 보조 버튼과 대기실 탭은 최소 44pt 높이를 확보합니다.
- 선택 상태는 기존 무광 표면과 테두리를 200ms로 전환합니다. 대기실 탭 본문은 교차 페이드하고 새 탭의 스크롤을 처음으로 돌립니다. 동작 줄이기에서는 선택·탭 애니메이션을 생략합니다.
- 메인 메뉴 패널과 스토리 선택·대기실의 구매/준비 화면은 짧은 페이드와 8pt 수직 이동을 사용합니다. 동작 줄이기에서는 이동 없이 120ms 페이드만 사용합니다. 애니메이션은 해당 선택·표시 상태에 한정하고 전투 수치나 입력에 전역 적용하지 않습니다.
- 스토리 선택은 상대 목록과 상세 정보를 각각 스크롤할 수 있습니다. 일반 글씨에서는 실제 복서 초상 옆에 이름·라운드·코너 조언·보상·접근 조건을 배치하고, 접근성 글씨에서는 장식 초상을 제외해 본문 공간을 확보합니다. 진행·이어하기·장면 다시 보기 행동은 본문 스크롤 바깥에 둡니다.
- 대기실은 일반 글씨에서 3D 미리보기와 선택 목록을 나누고, 접근성 글씨에서는 미리보기/착용/자세 요약을 넓은 본문 스크롤로 옮깁니다. 기본 세그먼트 피커는 상태와 접근성 ID를 갖춘 44pt 탭으로 교체했습니다. 스토리 준비의 시작 행동도 본문 밖에 유지합니다.
- 소유한 복장 탭 즉시 착용, 잠금 복장 미리보기, 자세·외형·스토리 접근 조건과 구매/복원 처리 규칙은 유지했습니다. `DEBUG`의 비저장 `menu` 검증 픽스처에서만 개발용 장비 전체 해금을 끄므로 실제 장비 조건을 검사할 수 있습니다. 일반 개발 실행과 배포 버전의 권한 동작은 바꾸지 않습니다. `story-selection` 픽스처 역시 진행을 저장하지 않으며 구매 성공을 만들어 넣지 않습니다.
- 복서·링·맵·메인 메뉴 대기 모션, 전투/AI·입력 시간·보상 계산과 나레이터 배너 부재는 유지합니다. 새 포스터 제작·리소스 추가·적용은 포함하지 않습니다.
- 검증: 집중 검사 24회(단위 9회, UI 15회; 기기별·후속 반복 실행 포함)가 유효한 결과 번들과 함께 통과했습니다. 큰 iPhone의 기본 집중 검사 15회, iPhone 12 mini의 메뉴/대기실/스토리 3회, 두 기기의 세 언어 스토리 본문 스크롤·준비창 취소 검사 2회, 큰 글씨 결과·스토리 코너/재도전·새로하기 취소 검사 4회입니다. 잠금 복장 미리보기 후 재입장 시 기존 착용 복장 유지, 44/48pt 행동 영역과 메뉴 초상/대기 모션도 검사했습니다.
- 서명된 iPhone SDK 빌드가 성공했습니다. 실제 시뮬레이터 화면과 녹화 프레임에서 선택 및 준비창의 진입·닫기 전환을 확인했습니다. 이번 버전은 실기기 연결을 사용할 수 없어 설치하지 못했으며, 실기기 터치감·햅틱·플레이 영향은 확인하지 않았습니다. 실제 구매/복원 거래와 전체 회귀 검증은 실행하지 않았고, 앞서 기록한 기존 단위 실패 5개도 이번 집중 범위에 포함하지 않습니다.

## 잽·크로스 인게임 모션 조정 (2026-11-06)

실제 경기의 플레이어·RIVAL과 체육관이 공유하는
[펀치 포즈 계산](PixelBoxingIOS/BoxingMotion.swift)을 수정했습니다.
검증 화면에서만 적용하는 효과나 Blender 클립 교체가 아니라 기존 절차적 모션의 조정입니다.

- **잽:** 발사 초반의 신전을 더 빠르게 읽히도록 조정하고, 몸통 회전 좌표가 아닌
  상대를 향한 좌표에서 주먹을 보간해 가드에서 목표까지 덜 돌아 나가게 했습니다.
- **크로스:** 뒤발 구동이 먼저 차고, 골반·흉곽·어깨가 뒤따르도록 초반 구동 곡선을
  조정했습니다. 접촉 때의 기존 회전량과 공격 시계는 유지합니다.
- **양쪽 직선 펀치:** 팔꿈치가 주먹 아래를 따라가도록 고정 길이 IK의 방향 힌트를
  조정하고, 회수 중 손을 위·안쪽으로 유도한 뒤 원래 스타일의 가드로 복귀합니다.
  회수 보정은 양 끝에서 0이며 동작 줄이기에서는 변위를 30%로 줄입니다.

외형·링·맵, 공격 지속 시간·접촉 기준 시각·피해·비용·사거리 수치는 변경하지 않았습니다.
다만 포즈와 접촉 판정이 코드를 공유하므로 모든 상황의 판정 불변을 가정하지 않습니다.
수정 전후 실제 엔진의 고정 더미 24개 조합(잽·크로스 × 거리 3개 × 방어 4개)에서
적중·가드·회피/헛스윙 결과, 상대 HP와 공격자 스태미나가 모두 같음을 비교했습니다.

새 모션 단위 검사 5개를 포함해 관련 단위·렌더·UI 검사 14개가 통과했고, 실제 경기
화면의 입력과 이동도 시뮬레이터에서 검사했습니다. iPhone SDK Release 빌드도 통과했습니다.
기존 `testProductionMotionRegressionMatrix` 1개는 여전히 실패하며 그 검사가 보고한
실패 30개는 수정 전 목록과 같음을 확인했습니다. 전체 모션 회귀 통과를 뜻하지 않습니다.
실제 공용 리그의 전후 66프레임씩을 동일 조건으로 렌더링해 비교했지만, 연결된 iPhone의
개발자 디스크 이미지 마운트 문제로 직접 플레이·햅틱·프레임 성능은 검증하지 못했습니다.
이동 중 모든 공격 조합과 사용자 손맛 개선은 추가 확인이 필요합니다.

## 인게임 모션 조정: 낮은 방어 자세에서 머리 공격 (2026-11-06 후속)

더킹·위빙에서 머리 훅을 칠 때 몸은 아래에 남고 팔만 머리를 향하던 연결을 수정했습니다.
좌우 훅과 낮은 자세의 좌우 어퍼컷이 대상이며, 실제 경기의 양측 선수·체육관·검증 렌더가
같은 포즈 계산을 사용합니다.

- 공격 준비 중에는 낮은 진입을 유지하고, 발사 중 무릎·골반·어깨를 함께 올립니다.
  다리의 신전은 장갑 도착보다 먼저 완성하며, 기존 숙임도 같은 비율로 풉니다.
  남은 웅크림을 보존해 완전히 뻣뻣하게 서지는 않습니다.
- 반대손은 올라오는 실제 턱을 따라갑니다. 팔·다리 길이와 발 접지 제약은 유지합니다.
  더킹을 계속 누르면 회수 뒤 그 방어 자세로, 위빙이 끝났으면 준비 자세로 복귀합니다.
- 공유 진입 포즈가 있는 실제 공격에는 렌더러의 위빙 자세 유지를 중복 적용하지 않습니다.
  바디샷의 낮은 레벨과 기존 잽·크로스 조정은 유지합니다.
- 피해·비용·사거리·공격 시계·위빙 이동량과 예약/취소 규칙은 변경하지 않았습니다.
  머리 접촉 위치도 같은 포즈를 따라 올라가며, 공격 중 더킹·위빙 회피 권한을
  별도로 부여하지 않습니다. 따라서 모든 상대 움직임에서 접촉 결과가 불변이라는 뜻은 아닙니다.

집중 검사 `RIVALTests/DefensivePunchMotionTests` 7개는 3개 스타일의 좌우 진입,
발사·접촉·회수 경계, 고정 관절 길이·접지, 반대손, 렌더/접촉 머리 높이,
실전/체육관의 훅 시작·비용과 공격 중 회피 불가를 검사합니다.
시뮬레이터에서 관련 단위·렌더 검사 28개와 일반 경기 UI 검사 1개가 통과했고,

  바디/어퍼컷도 손 회수 뒤 골반과 발이 기존 공격 종료까지 정리되도록 연결했습니다.
  이는 조작 후딜·취소창 변경이 아닙니다.
- 낮은 진입은 기존 구동을 유지합니다. 방어 낮춤 0.04 이상에서는 이전 발/골반 시계와
  하체 낮춤을 그대로 쓰고, 거의 선 자세로 돌아오는 마지막 구간에서만 부드럽게 섞습니다.
  앞서 개선한 더킹→머리 공격 상승과 결과별 회수도 유지합니다.

[PowerTransferMotionTests](PixelBoxingIOSTests/PowerTransferMotionTests.swift) 6개는

## Debug 모션 검증 장면

Debug 빌드의 Xcode Scheme > Run > Arguments에 `-rival-motion-lab`을 추가하거나
환경 변수 `RIVAL_MOTION_LAB=1`을 지정하면 일반 메뉴 대신 모션 검증 화면으로 시작합니다.
Release 빌드에는 이 화면과 실행 분기가 포함되지 않습니다.

- 실제 `CombatEngine`, `Arena3DScene`, 복서 리그를 사용해 잽·크로스와 가드 복귀를
  60Hz 고정 간격으로 재생합니다. 정상 속도·0.5배·0.25배, 일시 정지, 앞뒤 한 프레임,
  타임라인 탐색, 접촉 기준 프레임 이동과 반복 재생을 지원합니다.
- 근거리·중거리·거리 후보 상한과 무방비·가드·좌우 더킹 더미를 선택할 수 있습니다.
  거리 상한은 자동 적중 보장이 아니며 실제 궤적·방어 판정은 엔진이 결정합니다.
- 측면 검사 카메라와 실제 경기 카메라를 전환하고 머리 접촉 볼륨을 표시할 수 있습니다.
  `HIT`, `BLOCK`, `DODGED`, `MISS`는 실제 전투 이벤트에서 가져옵니다.
- 더미의 AI 선택만 긴 테스트 경직으로 막습니다. 시드가 고정된 비저장 엔진을 사용하며
  뒤로 탐색하면 엔진과 리그를 다시 생성해 같은 조건으로 재생합니다.
  일반 경기의 학습·통계·구매·보상·사운드·햅틱 흐름에는 진입하지 않습니다.

앱 내 전후 비교, 이동 중 공격과 자동 대전 검증은 아직 포함하지 않습니다.
프레임 0은 가드 준비이며 15프레임 뒤
공격을 시작합니다. 접촉·활성 종료 표시의 초 단위는 공격 시작 기준입니다.
가상 환경의 재생·수치 검사는 실제 iPhone의 입력감·햅틱·성능 검증을 대신하지 않습니다.

공개 GitHub 저장소에는 사용자 선택에 따라 외부 음원 원본과 앱용 음원 파일을 포함하지 않습니다.

이 공개 커밋 때문에 기존 로컬 파일이나 심사 제출된 빌드의 음원을 제거하지는 않습니다.
최종 스토어 이미지와 메타데이터는 추적하되, 이를 중복 압축한 배포 ZIP은 로컬에만 보관합니다.

### iPhone SDK 빌드

시뮬레이터를 실행하지 않고 generic iOS 대상으로 무서명 컴파일할 수 있습니다.
아래는 재현 명령이며 이번 문서 정리에서 실행하지 않았습니다.

```bash
cd ios-pixel-boxing
xcodebuild \
  -project RIVAL.xcodeproj \
  -scheme RIVAL \
  -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO \
  build-for-testing
```

심사에 사용한 실제 Xcode 프로젝트를 함께 보존합니다. `project.yml`은 유지된 명세이며,
XcodeGen 재생성 전 Story JSON 11개·개인정보 매니페스트·UI-test-only StoreKit fixture의
등록과 스킴을 확인해야 합니다. 문서 정리를 위해 프로젝트를 재생성하지 않습니다.

## 배포 직전 원클릭 점검

배포 직전 스크립트는 XcodeGen 재생성과 무서명 generic iOS `build-for-testing`·Release
컴파일을 실행하고, `--device-id`를 지정하면 실기기 `test-without-building`을 시도합니다.
무서명 컴파일만으로 실기기 설치·테스트나 배포가 보장되지는 않으며, 실기기 테스트에는
해당 기기에서 실행 가능한 서명된 테스트 산출물이 별도로 필요합니다.

```bash
cd ios-pixel-boxing
chmod +x scripts/pre_release_check.sh
./scripts/pre_release_check.sh --device-id <UDID>
```

체크 항목 상세는 [RELEASE_READINESS_CHECKLIST.md](../docs/release/RELEASE_READINESS_CHECKLIST.md)를 사용합니다.

## 실제 iPhone 및 TestFlight 배포

실기기용 `.app` 또는 `.ipa`는 Apple 서명이 필요하므로 저장소에서 공용 파일로 미리 생성할 수 없습니다.

1. 정식 앱 업데이트는 기존 `com.acertainromance401.pixelboxing` 식별자와 Team을 유지합니다. 별도 포크에만 다른 식별자를 사용합니다.
2. Xcode의 Signing & Capabilities에서 Team과 자동 서명을 선택합니다.
3. Product > Archive를 실행합니다.
4. Organizer에서 Distribute App > App Store Connect > Upload를 선택합니다.
5. App Store Connect에서 TestFlight 빌드를 심사 계정에 배포합니다.

App Store 제출 전에는 앱 이름, 아이콘, 개인정보 처리방침, 연령 등급, 스크린샷과 Apple Developer 계정 설정을 최종 확인해야 합니다.
