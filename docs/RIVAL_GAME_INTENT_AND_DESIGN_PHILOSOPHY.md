## 1. 한 문장 정의

**RIVAL은 적이 플레이어의 반복 습관을 읽고 성장하는 동안, 플레이어도 자신의 전략을 바꾸며 성장하게 만드는 3D 복싱 게임이다.**

RIVAL의 목표는 적의 체력이나 공격력만 올려 난이도를 높이는 것이 아니다. 같은 전투
규칙 안에서 적이 플레이어의 반복 행동에 대응하고, 플레이어는 그 대응을 읽어 공격,
회피, 거리, 스태미나 관리 방식을 바꾸게 만드는 것이 핵심이다.

## 2. 이 문서를 읽는 방법

| 표기 | 뜻 |
| --- | --- |
| **의도** | 개발자가 원하는 제품 경험 또는 앞으로도 지켜야 할 설계 방향 |
| **현재 구현** | 현재 iOS 소스에서 확인한 동작, 실행 근거는 해당 날짜·범위에 한정 |
| **검증 필요** | 플레이테스트, 실험 또는 비교 데이터가 있어야 사실로 말할 수 있는 주장 |
| **후속 과제** | 아직 구현하지 않았거나, 구현했더라도 경험 품질을 확인하지 못한 작업 |

고도화 작업에서는 새 기능을 먼저 만들기보다, 아래 질문에 답해야 한다.

1. 이 변경이 "RIVAL이 나를 읽고, 나는 전략을 바꾼다"는 순환을 강화하는가?
2. 플레이어의 실수나 반복을 읽을 수 있게 만들되, 적이 몰래 수치적으로 강해지는 느낌은 피하는가?
3. 실전의 몰입을 깨지 않고 필요한 정보만 올바른 시점에 주는가?
4. 현재 구현 사실, 목표, 검증 결과를 서로 섞지 않는가?

## 3. 게임을 보는 관점

개발자는 게임을 단순한 오락이나 기능 묶음이 아니라, 사용자의 선택과 체감이 가장
직접적으로 드러나는 콘텐츠로 본다. 입력 반응, 난이도, 보상, 협동과 경쟁의 규칙은
플레이어가 느끼는 재미와 관계를 바꾼다.

따라서 게임 개발은 시스템을 구현하는 일에 그치지 않는다. 플레이어가 다음 질문에
어떤 답을 느끼게 할지를 규칙, 피드백, 보상, UI와 콘텐츠로 설계하는 일이다.

- 이 게임을 처음 시작할 이유는 무엇인가?
- 한 판 뒤 다시 도전할 이유는 무엇인가?
- 오랫동안 플레이하며 이 게임과 적에게 애착을 느낄 이유는 무엇인가?
- 패배가 단순한 처벌이 아니라 다음 선택을 배우는 경험이 되려면 무엇이 필요한가?

## 4. RIVAL이라는 이름과 핵심 관계

RIVAL은 모든 플레이어에게 같은 방식으로 행동하는 일반 NPC가 아니라, **내 플레이
습관을 기억하고 나를 상대하기 위해 성장하는 라이벌**을 지향한다.

### RIVAL 관계의 의도

처음 구상에서는 플레이어 행동 패턴을 학습하는 적 AI를 강화학습으로 구현하려 했다.
최종 iOS 앱의 구현 방식은 규칙과 통계 기반 적응형 AI로 달라졌지만, 플레이어가 반복한
선택이 다음 라운드의 적 대응에 반영되어 "RIVAL이 나를 읽고 있다"고 느끼게 하려는
경험 목표는 유지됐다.

### RIVAL 관계의 현재 구현

- iOS RIVAL은 Q-table, 신경망, 보상 기반 정책 갱신을 사용하는 강화학습 모델이 아니다.
- `HabitMemory`는 완료된 모든 라운드에서 플레이어의 공격, 가드, 좌우 더킹, 백스텝, 전진과 후퇴를 장기 프로필로 저장한다. 최근 라운드의 표본은 이전 기록보다 더 크게 반영된다.
- 한 라운드 안에서는 학습 정책을 고정하고 관측만 수집한다. `tacticalRead`는 라운드 시작 때 이전 완료 라운드의 확정 프로필에서 정한다.
- 종료 시 승패와 무관하게 습관과 양측 공격 결과를 병합해 일반 경기의 `pixelBoxingHabitMemory`·`pixelBoxingRivalResults`에 저장하고 다음 라운드부터 반영한다. 스토리는 별도 진행·학습 저장을 사용한다.
- RIVAL은 현재 거리, 확정 습관·공격 결과, 고정 전술 읽기, 플레이어 노출 상태를 이용해 펀치, 회피와
  풋워크의 가중치를 조정한다. 압박에는 서클링·후퇴로, 반복 후퇴와 백스텝에는 거리 차단
  이동으로 대응한다.
- 거리·스태미나·눈에 보이는 공격에 대한 고정 정책의 상황 반응은 학습과 구분한다. `RecentHabitMemory`와 시간 감쇠 기반 실시간 학습은 제거됐으며 경기 중 관측으로 정책을 재평가하지 않는다.
- 승패와 무관하게 완료된 라운드의 관측치를 장기 프로필에 반영한다. 패배는 기억을 지우는 조건이 아니라 플레이어가 바꿔야 할 전략을 드러내는 신호다.
- 습관을 관측했다는 근거는 이전 완료 라운드의 확정 표본에서 계산한다. 이와 별도로
  `RivalDifficulty`는 라운드가 올라갈수록 대응 가중치, 판단·반응 간격, 이동 활용도와
  짧은 연계 빈도를 점진적으로 높인다. 라운드 숙련도를 학습 정확도나 새로운 관측으로
  취급하지 않으며 일반 RIVAL의 체력·피해·공격 사거리는 올리지 않는다. 스토리 강타형의 명시적 상대 수치는 아래 별도 기준을 따른다.

근거 코드: [CombatCore.swift](../ios-pixel-boxing/PixelBoxingIOS/CombatCore.swift)

### 표현의 경계

- 최종 iOS RIVAL을 "강화학습 게임"이라고 표현하지 않는다.
- 정확한 표현은 "규칙·통계 기반 적응형 라이벌 AI"다.
- 초기 C++ Q-learning 프로토타입과 Python RL 훈련 환경은 프로젝트의 발전 과정으로
  설명하되, 현재 앱의 런타임 기능과 혼동하지 않는다.

## 5. 플레이할 이유의 설계

### 처음 시작할 이유

RIVAL의 첫 진입 경험은 플레이어가 반복하는 전술에 적이 반응한다는 차별점에 있다.
초반에는 익숙한 공격 조합으로도 싸울 수 있지만, 라운드가 진행될수록 같은 방식이 잘
통하지 않아 플레이어가 자기 전술을 다시 생각하게 된다.

의도한 체감은 다음과 같다.

> 처음에는 내가 게임을 공략한다. 이후에는 RIVAL이 나를 공략한다. 그래서 다음 라운드에는 내가 먼저 전략을 바꿔야 한다.

### 계속 플레이할 이유

적응형 상대와 조작감은 첫 플레이의 흥미를 만들 수 있지만, 그것만으로는 지속 플레이의
이유가 되기 어렵다. 승수, 연승, 무피격, 스타일 숙련, 체육관 시간처럼 플레이 기록이
쌓일수록 코스튬을 해금하는 보상 구조를 사용한다.

보상은 플레이어의 공격력이나 체력 같은 전투 능력치를 높이지 않는다. 플레이어 능력치
상승이 적의 성장이라는 중심 컨셉을 약화시킬 수 있기 때문이다. 대신 코스튬과 기록은
플레이어의 시간, 숙련, 성취와 게임에 대한 애착을 남기는 보상이다.

### 검증 필요

의상 해금과 경기 기록만으로 장기 재방문 동기가 충분한지는 아직 사용자 연구나 비교
실험으로 검증되지 않았다. 새 보상은 전투 능력치 상승보다 "나와 RIVAL의 관계 기록"을
강화하는 방식이어야 한다.

## 6. 적의 성장과 플레이어의 성장

RIVAL의 컨셉은 적이 성장하는 게임이지만, 게임은 동시에 플레이어도 성장하게 해야 한다.

### 라운드 승패의 현재 처리

```text
플레이어 승리
  -> 이번 라운드 습관·공격 결과를 확정 프로필에 병합·저장
  -> 다음 라운드 시작 때 정책과 전술 읽기를 확정

플레이어 패배 또는 무승부
  -> 이번 라운드 습관·공격 결과를 확정 프로필에 병합·저장
  -> 패배 원인이 된 반복 전략을 다음 재도전에서 바꿔 대응
  -> 같은 라운드에서 재도전
  -> 공격, 회피, 거리, 타이밍을 바꿔 대응
```

이 구조에서 적의 성장은 플레이어를 일방적으로 막기 위한 장치가 아니라, 플레이어가
자신의 반복 전략을 바꾸며 더 높은 수준의 전투를 익히게 하는 도전이다.

### 전술 읽기의 경험 기준

플레이어가 다음 순서를 느낄 수 있어야 한다.

```text
내가 같은 선택을 반복한다
  -> 이번 라운드에는 관측만 누적한다
  -> 라운드 종료 뒤 짧은 코너 리포트가 그 변화의 방향을 확인한다
  -> 다음 라운드의 RIVAL이 확정된 습관에 맞춰 대응한다
  -> 나는 다른 전술을 실험하고, 완료 뒤 다음 대응에 반영된다
```

현재 `RIVAL'S CORNER`는 감지된 전술 읽기가 있을 때 라운드 종료 화면에 표시된다.
실전 중에는 AI, 학습률, 확률, 그래프 같은 기술적 표현을 전면에 두지 않는다.

### 후속 과제

다음 라운드에 반영되는 전술 읽기가 실제 플레이어에게 충분히 뚜렷한 변화로 느껴지는지는
실기기 플레이테스트로 확인해야 한다.

**과거 구현 메모(2026-09-09):** 당시에는 읽기를 0.9–1.7초 유지한 뒤 최근 관측으로 다시 선택하고,
최근 공격에 6초 만료를 적용했다. 이는 당시 구현 이력이며 현재 사양이 아니다.
2026-10-12 기준 최근 행동의 실시간 재평가·시간 감쇠 경로는 제거됐고 라운드 종료 때만 학습을 병합한다.

## 7. 전투 설계: 연타보다 판단

RIVAL은 공격 버튼을 빠르게 많이 누르는 사람이 이기기보다, 상대의 행동을 읽고 적절한
선택을 하는 사람이 이기도록 설계한다.

### 스태미나

#### 스태미나 설계 의도

스태미너 소진은 플레이를 멈추게 하는 단순한 페널티가 아니라 전투 국면을 바꾸는 장치다.
플레이어는 무리하게 공격을 계속하기보다 풋워크로 거리를 만들고, 회피로 살아남으며,
다시 공격할 타이밍을 판단해야 한다.

```text
공격 반복
  -> 스태미너 소진
  -> 공격 연계 중단
  -> 거리와 회피로 생존하며 회복 기회 탐색
  -> 재공격 또는 카운터 기회 탐색
```

#### 스태미나의 현재 구현

현재 iOS에서는 스태미나가 완전히 소진되면 공격, 기본 이동, 가드, 방향 더킹, 백스텝이
모두 탈진 시간 동안 제한되고, 노출 상태가 된다. 따라서 위의 "이동과 회피로 회복"은
현재 코드의 사실이 아니라 **의도와 구현의 차이**다.

근거 코드: [CombatCore.swift](../ios-pixel-boxing/PixelBoxingIOS/CombatCore.swift)의
`updatePlayerMovement`, `setGuarding`, `setDuck`, `backstep`, `exhaust`.

일반 스태미나 회복은 초당 11이며 탈진·공격·가드·더킹·위빙 중에는 회복하지 않는다.
기본 전진·횡이동은 속도 210에 스타일 배율, 후퇴는 스타일 보너스 없이 기본 속도의 0.5배다.
더킹 중 기본 이동도 0.5배이며 공격·가드·피격 경직·탈진·위빙·백스텝 중에는 기본 이동을 제한한다.
백스텝은 기본 비용 31에 스타일 배율을 적용하고 시작 방향의 반대로 최대 34를 0.18초 동안 이동한다.
즉시 좌표 이동이나 전체 동작 무적이 아니며 회피 구간은 0.035초 이상·0.18초 미만이다. 링·선수 충돌 경계를 따른다.

#### 개선 판단

향후 탈진 설계를 바꿀 때는 다음 중 하나를 명확히 선택한다.

1. 현재처럼 전 행동을 제한해 강한 리스크로 유지한다.
2. 공격과 스태미나 소비 회피만 제한하고, 느린 이동과 방향 더킹으로 회복 국면을 만든다.

두 방식을 섞어 문서에는 회피 가능하다고 쓰고 실제 게임에서는 모든 행동을 막는 상태를
남기지 않는다.

### 방향 더킹과 카운터

더킹은 많이 누른다고 유리해지는 행동이 아니다. 상대의 왼손 또는 오른손 머리 공격
방향에 맞는 방향으로 더킹해야 회피가 성공한다. 방향이 맞지 않으면 회피에 실패하고
피격된다.

정확한 회피 뒤 공격에 성공하면 카운터 피해 보너스를 제공한다. 이 규칙은 플레이어가
단순히 공격을 반복하는 대신, 상대의 공격 방향과 타이밍을 읽고 회피한 뒤 반격하도록
유도한다.

현재 더킹 회피는 방향이 일치하고 보간 더킹량이 0.70 이상이어야 한다. 진입 시간 0.09초에서
정지 자세 기준 약 0.063초가 필요하므로 버튼을 누르는 순간 즉시 회피가 완성되는 것은 아니다.

### 위빙과 실제 접촉 판정

위빙은 비용 9·동작 0.36초·훅 시작 0.23초·회피 종료 0.27초 미만·종료 뒤 입력 유예 0.12초·총 재시작 대기 0.48초다.
회피 진입은 `0.09 × 0.70 ≈ 0.063초`이며 맞는 방향의 머리 공격에만 적용한다. 진입부터 0.23초까지
최대 12 게임 단위를 측면 이동하고 링·선수 충돌 경계를 따른다. L 위빙→JAB은 왼훅, R 위빙→CROSS는 오른훅으로 연결하며
체육관은 위빙·훅 비용이 없다. 피격·탈진·일시정지·이탈·라운드 종료는 예약을 취소한다.

8종 공격은 `activeStart`~`activeEnd`에 공통 관절 포즈의 장갑 궤적과 목표 표면을 swept 접촉으로 검사한다.
공격 시작 조준·방향은 고정하며 상대 이동을 추적하지 않는다. 방어는 프레임 끝이 아니라 실제 접촉 시각의
가드·더킹·위빙·백스텝·무적 상태를 적용한다. 양측 후보를 먼저 계산한 뒤 공통 프레임 시작 대비 접촉 시간순으로 처리한다.
이 구현 설명은 모든 자세의 메시 접촉·사용자 손맛을 새로 검증했다는 뜻이 아니다.

근거: [Weaving.swift](../ios-pixel-boxing/PixelBoxingIOS/Weaving.swift),
[DefensiveMotion.swift](../ios-pixel-boxing/PixelBoxingIOS/DefensiveMotion.swift),
[BoxingMotion.swift](../ios-pixel-boxing/PixelBoxingIOS/BoxingMotion.swift).

#### RIVAL MOMENT: 회피로 배우는 카운터 타이밍

RIVAL MOMENT의 발동 기준은 **카운터 적중이 아니라 플레이어가 공격을 회피한 순간**이다.
플레이어가 머리 공격을 올바른 방향의 더킹·위빙으로 피하면, 해당 회피 시작 시각과 현재
전투 시간에서 진입 시간을 뺀 값으로 등급을 평가한다. 위빙도 공통 `rewardDodge` 경로의
등급·카운터 창·모먼트를 사용하며 별도 위빙 전용 연출로 구현된 것은 아니다.

| 회피 등급 | 현재 카운터 창 | 현재 연출 |
| --- | ---: | --- |
| Normal | 0.18초 | 일반 회피 피드백, 속도와 카메라 유지 |
| Good | 0.28초 | 매우 짧은 약한 카메라 줌, 속도 유지 |
| Accurate | 0.60초 | 과감한 줌과 $0.40\times$ 슬로모션 |
| Perfect | 0.80초 | 매우 과감한 줌과 $0.20\times$ 슬로모션 |

`Accurate`와 `Perfect`가 RIVAL MOMENT다. 슬로모션은 회피 판정이 난 바로 다음 프레임부터
시작하며, 플레이어 입력은 정상적으로 받는다. 카운터 창 안에 시작한 플레이어 공격은
펀치의 실제 적중 프레임이 슬로모션 때문에 뒤로 밀려도 카운터 입력으로 유지한다. Perfect
회피에서 시작한 카운터가 적중하면 `PERFECT COUNTER`를 짧게 표시하고, 강한 타격 반동,
카메라 흔들림, 충격음, 강한 햅틱을 사용한다. 카메라 줌은 이 순간에는 눈에 띄게 튀는
정도까지 과감하게 밀어붙이며, 대신 블렌드 응답 속도도 함께 높여 줌 자체가 느릿한 드리프트가
아니라 결정적인 한 번의 push-in으로 읽히게 한다.

현재 줌은 빠른 진입 → 유지 → 복귀 곡선과 작은 시야각 축소를 함께 사용한다. Accurate와
Perfect 회피에는 짧은 `COUNTER` 표시를 보조적으로 사용하고 공격을 시작하면 지운다.
이는 카메라만으로 타이밍을 알아차릴 수 있다는 사용자 검증을 대신하지 않는다.

이 연출은 플레이어의 등급 있는 더킹·위빙 회피에 적용한다. RIVAL의 회피, 가드, 백스텝, 일반 피격에는
발동하지 않으며, 카운터 피해량, 유효 입력, AI 선택 가중치를 바꾸지 않는다. 배경음은
현재 별도 트랙을 재생하지 않으므로 오디오 더킹을 주장하지 않는다. 향후 배경음이 추가될
때만 RIVAL MOMENT와 동기화한 볼륨 덕킹을 검토한다.

#### KO 모먼트: 라운드를 끝내는 마지막 일격 연출

RIVAL MOMENT와 별개로, 라운드를 끝내는 K.O. 타격 자체에도 전용 슬로모션과 카메라 줌을
건다. 발동 기준은 **해당 타격으로 상대의 체력이 0이 되는 순간**이며, RIVAL MOMENT의
Perfect 등급보다도 더 강한 $0.14\times$ 슬로모션과 더 큰 카메라 줌을 0.62초 동안 적용해
"이 한 방이 라운드를 끝냈다"는 것을 명확히 인지시킨다. 만약 Perfect 카운터 창 안에서
K.O.가 나면(퍼펙트 회피로 마무리한 K.O.), KO 모먼트가 RIVAL MOMENT보다 우선한다 —
"카운터가 성공했다"보다 "이걸로 끝났다"가 더 지배적인 신호여야 하기 때문이다. KO
모먼트가 진행되는 동안 넉다운 낙하 애니메이션 자체도 함께 느려지므로, 라운드 종료
오버레이가 뜨기 전 짧은 순간 동안 쓰러지는 모습이 슬로모션으로 보인다.

2026-09-07 감사에서 이전 화면은 `.roundBreak` 진입 즉시 결과창을 표시해 위 의도와
충돌함을 확인했다. 현재는 KO 뒤 시뮬레이션 시간 0.95초가 지나 낙하가 끝난 다음 결과를
공개한다. 일반 판정 종료는 0.35초의 짧은 휴식 뒤 공개한다. 기존 다음 라운드 확인 버튼과
대기 시간은 유지한다. 승자의 마지막 펀치는 피격 판정을 다시 하지 않고 회수 동작만 마친다.

2026-09-10에는 사용자가 K.O. 글자가 캐릭터를 가린다고 피드백해, 제안한 소규모 표시
변경만 승인했다. 독립된 32pt·검정 배경 K.O. 배너를 제거하고 기존 상단 타이머 칸에
22pt 응축형 흰 글씨와 얕은 그림자로 표시한다. 실제 프레젠테이션 시간으로 적중 후
0.2초 기다린 뒤 0.6초의 표시 상태를 유지하고, 0.1초 투명도 전환만 사용한다. 타이머
칸은 KO 휴식 동안 예약해 숫자와 K.O.가 겹치지 않으며 다음 라운드에서 숫자로 복귀한다.
KO 휴식 중 조작 버튼은 숨기되 일반 판정 종료는 기존 25% 표시를 유지한다. 카운터
배너, 카메라·슬로모션, 결과 패널과 공개 시점은 변경하지 않았다. 실제 화면의 가림
감소와 가독성은 사용자 실기기 확인이 필요하다.

**범위의 경계:** 일반 RIVAL의 KO 종료와 스토리의 다운·카운트·기상·TKO 규칙은 구분한다.
KO를 낼 공격을 적중 전에 예측하는 기능과 완전 정지형 Hit Stop은 구현하지 않았다.
현재 효과는 실제 종료 타격에서 시작하는 슬로모션이며 ‘KO 직전 예측’으로 표현하지 않는다.

```text
상대 공격 방향과 거리 관찰
  -> 맞는 방향의 더킹 또는 풋워크 선택
  -> 회피 성공
  -> 카운터 기회
  -> 더 큰 피해와 전략적 성취
```

이 구조는 강화학습의 상태, 행동, 보상이라는 사고방식과 닿아 있다. 다만 현재 iOS 앱이
강화학습으로 동작한다는 뜻은 아니다. 플레이어가 상태를 읽고 행동을 선택하며 결과를
통해 다음 전략을 바꾸는 게임플레이 구조라는 뜻이다.

## 8. 발견하게 하는 온보딩

RIVAL은 기본적으로 `JAB`, `CROSS` 두 공격 버튼을 제공하지만, 가드, 왼쪽 더킹, 오른쪽
더킹 상태와 결합하면 총 8종 공격으로 확장된다.

### 발견형 온보딩의 의도

모든 조합을 게임 시작부터 목록으로 외우게 하기보다, 플레이어가 직접 입력을 시도하고
다른 공격 모션과 결과를 발견하며 전투 규칙을 자기 경험으로 익히게 한다.

체육관은 이 발견을 위한 안전한 실험 공간이다.

- 스태미나 소모 없이 조작 버튼과 상태 조합을 자유롭게 시도할 수 있다.
- 공격마다 달라지는 모션과 피해 수치를 확인할 수 있다.
- 관장 NPC의 말풍선이 공격 조합과 전투 방식의 단서를 제공한다.
- 힌트를 모두 직접 설명하지 않고, 하나씩 찾는 즐거움을 남긴다.

체육관은 완전히 불친절한 방치가 아니라, 실패 비용은 낮추되 발견의 성취는 유지하는
선택적 친절의 장치다.

### 개선 기준

발견형 온보딩은 필수 조합을 모른 채 패배하는 상태가 되어서는 안 된다. 새 힌트는 긴
설명문 대신 다음처럼 경기와 체육관의 맥락 안에서 제공한다.

- 올바른 더킹 성공 뒤, 카운터 창을 시각·소리·햅틱으로 구분한다.
- 반복 습관이 읽힌 뒤, 체육관의 관장 힌트가 그 대응을 깨는 조합을 암시한다.
- 처음 보는 조합은 실행 결과와 모션 차이만으로도 알아차릴 수 있게 만든다.

## 9. 정보 설계: 실전은 체감, 연습은 수치

정보를 많이 보여 주는 것이 항상 좋은 UX는 아니다. 플레이어가 어느 순간에는 정확한
수치를 통해 실험해야 하지만, 실제 경기에서는 숫자보다 전투의 흐름과 감각을 읽어야
한다.

| 공간 | 제공 정보 | 설계 목적 |
| --- | --- | --- |
| 체육관 | 공격 모션과 피해 수치 | 공격 조합과 효율을 안전하게 실험하고 비교 |
| 실전 경기장 | 일반 타격 피해 수치 비노출, 전투 나레이션과 감각적 피드백 | 수치 최적화보다 거리, 타이밍, 타격감, 상대 움직임에 몰입 |
| 라운드 종료 | 양측 주요 공격과 회피 수, 감지된 RIVAL 전술 읽기 | 방금 전투를 다음 전략을 세우는 정보로 전환 |

### 현재 구현의 주의점

기본 적중 피해 수치는 실전 HUD에 별도 숫자로 표시하지 않는다. 다만 카운터 나레이션은
보너스 피해량을 숫자로 포함할 수 있다. 따라서 "실전 피해 수치 완전 비노출"이 아니라
"일반 타격 수치는 비노출, 카운터 보너스는 제한적으로 수치 노출"이 현재 사실에 맞다.

근거 코드: [CombatCore.swift](../ios-pixel-boxing/PixelBoxingIOS/CombatCore.swift)의
`CombatCommentary.counter`, [GameView.swift](../ios-pixel-boxing/PixelBoxingIOS/GameView.swift).

실전 경기에서는 회피 성공과 카운터에 다른 행동과 구분되는 소리와 진동을 부여해,
플레이어가 수치 계산보다 "지금 잘 피했다"와 "지금 반격 기회를 만들었다"를 감각적으로
익히게 한다.

## 10. UI/UX와 연출의 역할

RIVAL의 UI는 AI 도구나 데이터 대시보드처럼 보여서는 안 된다. 시각 언어는 복싱 중계,
선수 대기실, 링 위의 긴장감에서 가져온다.

### 원칙

- 현재 복서 캐릭터와 링·맵 디자인은 승인된 기준으로 유지한다. 고도화는 캐릭터나 맵을
  다시 디자인하는 대신, 화면 구성, 조작감, 정보 위계, 조명과 연출의 완성도를 높이는 데
  집중한다.
- 시각 언어는 "심플하지만 고급스러움"을 따른다. 깊은 단색, 매트한 검정, 절제된 테두리와
  그림자로 대비를 만들며, 시각적 복잡성보다 전투 선택의 깊이를 우선한다.
- 실전 전투 조작 버튼에는 색상 그라데이션을 사용하지 않는다. 펀치, 방어, 이동의 구분은
  단색 청색·적색·금색과 명확한 눌림 상태로 만든다.
- 장식 목적의 그라데이션, 과도한 유리 질감, 상시 광택과 발광은 기본값으로 사용하지 않는다.
  예외는 정보 위계나 가독성에 명확한 이득이 있고 개발자의 별도 승인을 받은 경우에만 둔다.
- 실전 HUD는 방송형 체력·스태미나·라운드 정보와 짧은 경기 피드백을 우선한다.
- 터치 조작부는 왼쪽의 이동·방어와 오른쪽의 공격이라는 엄지 역할이 즉시 구분되어야 한다.
- `AI`, `학습률`, 그래프, 뇌 아이콘, 기술 설명은 실전 전면 UI에 사용하지 않는다.
- RIVAL의 적응은 우선 자세, 풋워크, 회피, 공격 순서로 보여 주고, 라운드 종료 리포트는
  이를 짧게 확인해 주는 역할만 맡는다.
- 고급화는 모든 화면에 같은 유리 카드나 광택 효과를 반복하는 일이 아니라, 각 화면이
  경기장, 코너, 대기실, 체육관이라는 장소성을 갖게 만드는 일이다.

### 입장과 컷신

첫 경기의 입장 연출은 RIVAL과 플레이어의 대치 관계를 보여 주는 짧은 감정적 시작점이다.
현재 앱 실행 오프닝은 정적인 로딩 아트 대신 SceneKit 링과 복서를 재사용한 짧은 전투
안무를 재생한다. 대각선 측면의 넓은 구도에서 두 선수의 가드, 잽, 더킹, 크로스, 훅을
보여 준 뒤 가까운 거리로 진입한다. 이 연출은 실제 `CombatEngine`을 갱신하지 않고 렌더링
상태만 임시로 바꾸며, 종료 시 기존 선수 상태를 복원한다. 따라서 피해 판정, AI 선택,
장기 습관 기록, 전투 밸런스에 영향을 주지 않는다. Reduce Motion 환경에서는 축소된 전환을
사용한다.

향후 컷신은 길이를 늘리는 것보다, RIVAL이 이번 라운드에 어떤 전술을 준비하는지 자세와
카메라 구도로 암시해야 한다. 사이버 연출이나 "AI가 학습했다"는 직접 표현은 피한다.

## 11. 적응형 AI의 구현 경로와 기술 경계

### 구현 경로

1. **초기 C++ TUI:** 온라인 Q-learning, Q-table 갱신과 저장, 전투 루프 연결을 구현했다.
2. **Python 단계:** 상태 전이, 행동 마스킹, 보상 이벤트, 렌더링 없는 시뮬레이터를 갖춘
   RL 훈련 환경을 구현했다. 정책 학습과 저장·로드는 완성하지 않았다.
3. **최종 iOS 앱:** 플레이어 행동 통계를 `HabitMemory`에 누적하고, 사전에 정의한 규칙과
   가중치로 RIVAL의 행동 선택 확률과 판단 빈도를 조정하는 설명 가능한 적응형 AI를 구현했다.

상세한 사실 검증은 [RIVAL 강화학습 구현 및 최종 적응형 AI 검증 기록](../ios-pixel-boxing/RIVAL_REINFORCEMENT_LEARNING_AUDIT.md)을 따른다.

### 강화학습을 다시 검토할 조건

진짜 강화학습은 기술 이름을 붙이기 위해 추가하지 않는다. 다음 조건이 충족될 때만
오프라인 정책 훈련을 검토한다.

1. Swift 실전 규칙과 헤드리스 학습 환경의 상태 전이와 판정 결과가 동등하게 검증된다.
2. 상태, 유효 행동 마스크, 선택 행동, 결과 보상, 정책 버전을 재현 가능한 로그로 남긴다.
3. 무작위 AI와 현재 규칙 기반 AI를 상대로 승률뿐 아니라 행동 다양성, 반복 억제, 난이도
   안정성을 비교한다.
4. 학습된 정책은 먼저 읽기 전용으로 iPhone에 탑재하고, 플레이 중 온라인 정책 갱신은
   공정성과 디버깅 기준을 충족하기 전까지 활성화하지 않는다.

강화학습이 들어가더라도 플레이어가 보는 것은 "AI 모델"이 아니라 RIVAL의 복싱 전술과
자신의 전략 변화여야 한다.

## 12. 고도화 우선순위

다음 순서를 지킨다. 시각적 장식이나 기술 교체가 핵심 전투 순환보다 앞서지 않는다.

1. **전투 주도권:** 탈진, 거리, 방향 더킹, 카운터가 플레이어에게 전략 전환의 기회를
   실제로 제공하는지 검증한다.
2. **읽히는 RIVAL:** 반복 습관에 대한 적의 행동 변화가 실제 플레이에서 식별 가능한지
   확인하고, 대응을 깨면 RIVAL도 전환되는지 검증한다.
3. **발견형 온보딩:** 체육관, 모션, 감각 피드백과 맥락형 힌트로 필수 선택지를 발견하게 한다.
4. **관계 기록과 보상:** 코스튬, 승수, 연승, 무피격, 스타일 숙련, 체육관 기록을
   "나와 RIVAL의 경기 이력"으로 보이게 한다.
5. **프리미엄 프레젠테이션:** 반응형 HUD, 터치 조작감, 입장·라운드·KO 연출, 장소성을
   고급화한다.
6. **오프라인 RL 실험:** 위 경험이 안정된 뒤 정책 학습과 평가를 별도 실험 경로로 진행한다.

### 2026-09-10 승인 — 더킹·위빙·바디 어퍼컷과 공간 디테일

사용자는 합의한 더킹 개선, 작은 실제 측면 이동을 동반하는 위빙과 같은 쪽 훅,
바디 어퍼컷에 가까운 바디샷 모션 및 맵 제안 적용을 승인했다. **경기장 조명은 매우
만족하므로 보존**, 체육관은 개선, 사우스포는 추후 별도 업데이트라는 범위를 따른다.

- **더킹:** 무릎·고관절을 굽혀 골반과 상체를 낮추고, 방향 쪽 작은 yaw·전방 pitch를
  합성한다. 기존 큰 횡이동·roll은 줄이고, 장갑·팔꿈치는 실제 렌더 머리의 턱 상대 위치를
  따른다. 발 지지는 보존하며 기존 더킹 입력 조합·회피 판정은 바꾸지 않는다.
- **위빙:** 이동 패드 위쪽 대각선 빈칸 두 곳에 버튼을 추가한다. 0.36초 U자 하강·통과·상승,
  0.06–0.22초 최대 12 게임 단위 측면 이동을 기존 링·충돌/체육관 경계 안에서 수행한다.
  실전 비용 12, 재시작 대기 총 0.48초이며 홀드 반복은 없다. 머리 공격은 방향이 일치하는
  0.06–0.24초에만 회피한다. 바디·반대 방향·공격 중에는 적용하지 않는다. 일반 회피 수와
  기존 노출 카운터 규칙을 재사용하지만, 위빙 전용 피해 배율·무적·모먼트는 만들지 않는다.
- **연계:** 왼 위빙+JAB→왼훅, 오른 위빙+CROSS→오른훅이다. 한 번의 조기 입력을 예약해
  0.22초 이후 실행하고 동작 종료 뒤 0.12초 입력 유예를 둔다. 공격 비용은 실제 발동 시
  지불한다. 피격·탈진·일시정지·이탈·라운드 종료 시 예약은 취소된다. 낮은 위빙 진입 자세는
  훅 접촉까지 시각적으로 유지한 뒤 회수하며 풀되, 회피 시간은 연장하지 않는다.
- **바디샷:** 기존 좌우 공격 ID·피해·시간·사거리는 그대로, 준비 높이 1.08에서 복부
  접촉 높이 1.35로 올라오는 짧은 상승 궤적과 굽힌 팔꿈치를 사용한다. 머리 어퍼컷과 구분한다.
- **AI·저장:** 실제 실행된 최근 위빙 반복만 라운드 한정으로 감쇠 관측해 바디 대응 가중치를
  제한적으로 높인다. 예약된 훅 입력은 AI가 보지 않는다. 기존 장기 습관 저장 스키마·키는
  변경하지 않으며 위빙 전용 장기 학습·읽기 카테고리·AI 위빙 선택은 이번 범위에 없다.
- **체육관:** 위빙·연계 훅도 기존처럼 스태미나 비용 없이 훈련한다. 세 언어 안내를 추가한다.
- **맵:** 경기장 조명·노출·블룸·카메라·링 크기를 보존한다. 낮은 대비의 캔버스 질감,
  기존 원형 중앙 문양의 평면 인쇄, 코너 끈·로프 연결부·외벽 이음새와 정돈된 관중 52명/
  좌석 84개를 사용한다. 체육관은 기존 크기·동선·샌드백·관장·거울을 유지하고 판재 바닥,
  저상 벤치·수건·장갑·장비 받침, 샌드백 지지보, 작은 RIVAL 표지·복싱 그림 포스터를 추가한다.

### 2026-09-09 자세·모션 전반 개선 — 사용자 일괄 승인

사용자가 기본 자세, 공격의 준비·접촉·회수, 몸통 회전, 피격 방향성, 발 고정,
방어 전환, 상·하체 합성과 짧은 강타 연출을 모두 진행하도록 승인했다.
이 범위는 **렌더링 전용**이며 AI, 피해·사거리·공격 시간·카운터 창, 이동 가능 조건,
저장 키, 복서·링 지오메트리와 조작부 배치는 변경하지 않았다.

- **준비 자세:** 상체의 작은 전방 경사와 연결된 호흡·체중 이동을 적용한다. 인파이터는
  기본 장갑을 올리고 팔꿈치를 소폭 안으로 모은다. 아웃복서의 비대칭 셸과 슬러거의
  낮고 넓은 기본 가드는 유지한다. 머리·목은 상체 회전의 일부를 따라가며 분리를 줄인다.
- **공격:** 골반의 짧은 사전 비틀림 뒤 흉곽·어깨가 이어진다. 8종 모두 기존 `activeStart`
  접촉 정점과 원래 자세 복귀를 유지하고, 훅·바디·어퍼컷의 궤적을 보존한다. 비타격 손의
  장갑뿐 아니라 팔꿈치도 함께 가드로 올라온다. 기존 공격 시간을 새 공통 시간으로
  덮어쓰거나 입력 지연을 더하지 않는다.
- **풋워크·레이어:** `FootPlantMotion`이 월드 좌표의 지지발 하나를 유지하고 반대발을
  내딛는다. 횡이동은 이동 방향 쪽 발이 먼저 나가고 최소 좌우 간격을 둔다. 공격 진입으로
  엔진 이동이 멈춰도 진행 중인 스텝은 마무리한다. 이는 이동 중 공격을 허용하는 규칙
  변경이 아니다. 정지 뒤 발 재정렬, 방향 회전, 백스텝·KO·위치 재설정을 별도로 처리한다.
- **방어:** 가드 진입·복귀와 방향 더킹에 별도 보간 응답을 사용한다. 더킹 시 장갑·팔꿈치는
  머리를 따라 낮아지되 턱 대비 가드 높이는 유지한다. 어깨는 몸통 부착점에서 옆으로
  분리하지 않는다. 보간은 시각 값뿐이며 실제 방어 판정은 엔진 상태를 그대로 따른다.
- **피격:** 머리·어깨의 좌우 반응과 바디 접힘을 분리하고, 빠른 충격 성분과 느린 복귀
  성분을 합친 감쇠 곡선을 사용한다. 기존 일반 반동 최대 진폭과 0.24초 종료를 유지하며
  가드는 장갑 압축 중심이다. 동작 줄이기·KO에는 기존 감쇠 곡선을 유지한다.
- **강타 연출:** 확인된 비가드 강타의 접촉 뒤 회수·피격에만 80ms 시각 펄스를 적용한다.
  시각 시간의 속도가 잠시 최저 0.92배가 된 뒤 같은 구간 안에서 따라잡으며 지연은 최대
  약 2.04ms다. 엔진 시간·판정 전 공격에는 적용하지 않는다. 접촉 이벤트는 별도의 최대
  33ms 카메라 킥도 구동한다. 약타·일반 가드는 새 펄스/킥을 사용하지 않고, KO·회피
  모먼트가 활성화되면 기존 전용 연출을 우선한다. 새 효과는 동작 줄이기에서 끈다.
- **체육관:** 같은 공격 회수 펄스·카메라 접촉 타임라인을 공유한다. 샌드백 타격 때
  플레이어의 타격 알림 값을 피격 반동으로 해석하던 렌더링 경로를 차단한다.

**검증:** 실제 앱의 순수 포즈·모션 소스를 macOS에서 직접 컴파일해 8종 공격 × 3개
스타일 × 더킹 상태, 30/60/120fps 방향별 발 고정·복귀, 회전·일시정지·순간 위치 변경,

44,189개나 실기기 플레이 결과가 아니다. iPhone SDK `build-for-testing`도 성공했다.
전체 iOS XCTest 실행, 실기기 설치·시각/조작/햅틱 체감, 장시간 발열·FPS와 App Store

- **지속적인 라이벌 읽기:** 완료된 모든 라운드의 습관을 장기 프로필에 병합하고, 최근

  플레이어가 다음 라운드를 선택하도록 했다. 결과를 읽고 전략을 바꾸는 시간을 보장한다.

  일본어 설정을 따른다.
- **관계 기록과 보상:** 승수, 연승, 무피격 라운드, 스타일별 승리, 체육관 시간을 로컬에

  어두운 표면과 깊은 팀 색상으로 역할을 구분한다.
- **선택적 온라인 기록:** Game Center 총승 리더보드를 연결했다. 네트워크, 로그인 또는
  App Store Connect 리더보드 설정이 없으면 경기 진행을 막지 않는 선택 기능이다.

### 2026-09-07 메인 메뉴 아트디렉션 — 2차 적용

### 2026-09-07 내부 메뉴와 잽·크로스 — 3차 적용

사용자는 전체 화면 대기실·랭킹과 작은 설정 패널, 경쾌한 잽과 묵직한 강타의 대비를
승인했다. 두 범위를 나눠 내부 메뉴를 먼저 실기기로 확인한 뒤 모션을 연결했다.

#### 내부 메뉴의 현재 구현

- 대기실·랭킹은 차콜 전체 화면, 설정·새로하기는 작은 패널로 구성한다. 공용 헤더,
  아이보리 텍스트, 응축형 제목, 4pt 메뉴 버튼과 중립색 선택 행을 사용한다.
- 대기실의 스타일/의상 탭은 큰 미리보기와 분리한다. 잠긴 의상도 미리보기 가능하지만
  실제 장착은 기존 해금 조건을 통과해야 한다. 미리보기와 착용 중 표시를 구분한다.
- 랭킹은 기존 Game Center 기록만 사용하며 로그인·로딩·빈 결과·오류 상태를 유지한다.
  닫은 화면으로 늦은 비동기 응답이 돌아오지 않도록 취소를 확인한다. 실제 온라인 순위
  데이터의 성공 조회·제출은 이번 UI 검증에서 확인한 항목이 아니다.
- 체육관은 기존 공간·샌드백·관장을 유지하고 상단/나가기와 조작부를 통일한다. 상단을
  3D 뷰 바깥에 두어 관장 말풍선을 가리지 않는다. 무제한 연습에서는 변하지 않는 HP·
  스태미나 막대 대신 스태미나 비용이 없음을 짧게 안내한다.
- 전투·체육관 버튼은 기존 역할별 색과 터치 영역을 유지하며 모서리·서체를 정리하고
  눌렀을 때 색상 발광 그림자를 제거한다. 대기실 턴테이블은 동작 줄이기에서 정지한다.

#### 잽·크로스와 피격의 현재 구현

- `StraightPunchMotion`은 기존 잽 0.08초·크로스 0.14초의 `activeStart`에 주먹 신전 정점을
  맞춘다. 공격 전체 시간·피해·사거리·스태미나 비용·회피 입력 창·AI 규칙은 변경하지 않았다.
- 크로스의 뒷발 피벗·무릎·골반이 먼저 움직이고 상체가 이어받도록 하되, 앞발은 상체 회전에
  끌려 돌지 않는다. 잽은 회전 폭을 작게 하고 손을 더 빨리 회수한다. 동작의 끝에는 기존
  스타일·더킹 자세의 팔 위치로 복귀한다.
- 강한 상체 회전 때문에 주먹이 옆으로 빠지지 않도록 복서 전방 목표점을 역변환한다.
  실전에서는 시각적 신전 거리를 상대 거리와 스타일 리치에 맞추고 최대 길이를 제한한다.
  이는 메시 충돌 판정을 추가한 것이 아니며, 모든 각도·회피 자세에서 정확한 접촉을
  보장했다는 뜻도 아니다. 체육관의 샌드백 표면에 맞춘 별도 신전 보정은 아직 없다.
- 피격 이벤트를 받는 복서별로 머리 반동, 바디 접힘, 가드의 장갑 압축을 분리한다.
  접촉 지점에는 0.045–0.065초의 작은 비발광 선 3개를 재사용하고, 실전 일반 피격의
  전신 섬광은 대신 사용하지 않는다. 동작 줄이기에서는 선을 숨기고 반동 변위를 줄인다.
- 실기기 렌더에서 신전 때 팔꿈치 캡슐 끝이 갈라져 보이는 부분을 확인해 기존 팔·소매
  연결부만 조금 겹치게 했다. 복서의 기본 형태와 링·맵 디자인은 유지했다.
- 패배 문구에 남아 있던 과거 ‘학습 롤백’ 표현도 현재의 완료 라운드 습관 보존 규칙에 맞춰
  세 언어에서 같은 라운드 재도전 안내로 수정했다.

#### 검증과 경계

- iPhone 12 mini에서 단위 테스트 **82개**, UI 테스트 **11개** 통과. 메뉴 왕복·잠긴 의상
  미리보기·새로하기 취소·큰 글씨·동작 줄이기·기존 카운터/KO 흐름을 포함한다.

  측면 카메라는 실제 전투 카메라가 아니며, 사진 확인은 실시간 플레이 체감을 대체하지 않는다.
- Debug·Release iPhone SDK 빌드 성공. UI 테스트 전용 진입 플래그는 Release 바이너리에서
  제외됨을 확인했고, 일반 Debug 빌드를 기존 앱 삭제 없이 실기기에 설치·실행했다.
- 훅·어퍼컷·바디샷 공격 모션의 전체 재설계, 자동 조준·방어 판정 변경, Hit Stop 추가,
  장시간 발열·프레임·음향·햅틱 체감 검증은 아직 진행하지 않았다. 다음 확대는 플레이
  피드백을 받은 뒤 별도 범위로 진행한다. App Store 업로드는 하지 않았다.

### 2026-09-09 플레이 피드백 — 피격 반동·햅틱 소폭 조정

사용자가 피격 반동과 진동이 약하다고 느껴 소폭 강화를 요청했다. 이번 적용은 피드백에
한정하며 **AI 분석·개선 제안은 승인 대기**다. AI 가중치·관측·저장, 피해·경직·사거리·
카운터 창, 카메라와 복서·링 형태는 이번에 변경하지 않았다.

- 일반 피격의 뒤로 밀림·머리 변위·상체 반응은 기존 곡선에 1.18배, 가드의 장갑 압축은
  1.06배를 적용했다. 피격 지속시간 0.24초와 감쇠 곡선은 그대로다. 이는 리그의 시각 반응이며
  실제 복서 좌표나 전투 거리를 바꾸는 넉백이 아니다.
- 동작 줄이기에서는 추가 증폭 없이 기존 축소 반응을 유지한다. KO 피격 진폭과 별도 낙하
  동작도 유지한다.
- 햅틱 입력 강도는 잽 0.32→0.38, 크로스 0.62→0.69, 바디 0.52→0.59, 훅 0.68→0.75,
  어퍼컷 0.76→0.83, 가드 0.26→0.30, 가드 붕괴 0.85→0.90이다. KO는 최대 1.0을 유지한다.
  이 값은 API 입력값이며, 실제 진동 세기가 같은 비율로 증가했다는 측정 결과가 아니다.
- 사용되지 않던 `ImpactFeedback`과 실제 호출 경로의 중복을 정리해 실전·체육관의 햅틱과
  타격음이 하나의 프로필을 읽는다. 기존 실사용 음색·음량·햅틱 종류·이벤트 우선순위는
  보존한다. 미사용 프로필에만 있던 별도 카운터 증폭은 이번 소폭 증가에 중첩하지 않는다.

**확인 범위:** 반동 증폭·감쇠·동작 줄이기·KO 보존, 햅틱 강도·음량 보존 회귀 테스트를
추가하고 iPhone SDK `build-for-testing` 컴파일을 통과했다. 이번에는 테스트 실행,
실기기 설치·플레이·햅틱 체감 확인을 하지 않았다. 손맛 개선 여부는 사용자 확인이 필요하다.

### 2026-09-09 후속 승인 — 후반 AI·조합 입력·공격/회피 모션

사용자는 약 200라운드에서도 RIVAL이 거의 이기지 못하고 풋워크가 적다고 피드백했다.
이에 **라운드에 따른 점진적인 대응 강화**를 명시적으로 승인했다. 앞선 표본량 전용
난이도 방침은 이 피드백에 따라 수정하되, 관측된 습관과 상대의 전술 실행 능력은 분리한다.

#### 이번 구현

- **관측:** 상대 기준 전진·횡이동 입력을 월드 축으로 재투영하던 오류를 수정했다.
  공격·가드·경직·탈진으로 실행할 수 없던 이동 입력은 전진·후퇴 표본에서 제외한다.
  벽에 막힌 이동까지 실제 변위로 측정하는 방식은 아직 아니다. 최근 6개 공격에는 6초
  만료를 추가했으며 장기 저장 구조·키와 완료 라운드 82% 유지 방식은 그대로다.
- **숙련 곡선:** `experience = 1 - exp(-(round - 1) / 55)`로 초반과 후반을 나눈다.
  아래 값은 설계된 입력 계수이며 측정된 사람 상대 승률이나 학습 정확도가 아니다.

  | 라운드 | 기본 판단 간격 | 정면 이동 예산 | 습관 대응 배율 |
  | --- | ---: | ---: | ---: |
  | 1 | 1.000초 | 75.6/s | 0.45 |
  | 20 | 0.766초 | 110.6/s | 0.99 |
  | 50 | 0.528초 | 146.2/s | 1.54 |
  | 100 | 0.332초 | 175.5/s | 1.99 |
  | 200 | 0.221초 | 192.1/s | 2.25 |

  판단 간격에는 별도 작은 무작위 지연이 더해진다. 이동 예산은 플레이어와 같은 기준
  210/s의 최대 93%이며 후퇴 0.5배·스타일 배율·이동 중단 조건을 적용한다. 초반은 대기와
  단발 위주, 후반은 잦은 위치 조절과 최대 두 공격의 짧은 연계를 시도한다.
- **실행:** 사거리 밖·스태미나 부족 공격을 추첨 후보에서 제외한다. 기존에 기본 접근이
  멈추던 95–112 거리에서도 유효 타격 거리로 이동한다. 읽기와 스태미나에 맞는 거리
  유지·서클링·거리 차단을 지속하며, 공격·경직·탈진·방어 동작 중에는 이동하지 않는다.
  후반의 가드·방향 회피는 눈에 보이는 준비 동작을 일정 시간 관찰한 뒤 한 펀치당 한 번
  확률적으로 시도한다. 입력 큐나 미래 적중 결과는 보지 않는다.
- **공정성:** 체력·피해·공격 지속시간·사거리·플레이어 입력 창을 변경하지 않았다.
  RIVAL 백스텝은 플레이어와 동일한 기본 비용 31·거리 34·무적 0.22초로 맞췄다.
  RIVAL 더킹의 기존 비용 17과 지속 0.32초는 유지한다. 라운드 숙련은 상한이 있고 새로하기를
  선택하면 초반 수준으로 돌아간다. 기존 200라운드 저장을 다시 시작할 필요는 없다.
- **조작:** 가드는 이동키 중앙, 좌우 더킹은 이동키 양옆 아래에 유지한다. 공격을 손을
  뗄 때가 아닌 터치 시작에 한 번 입력하고, 현재 조합의 짧은 다국어 공격명을 버튼에
  표시한다. 겹친 더킹은 마지막으로 누른 방향을 사용하고 이를 놓으면 남은 방향으로
  복귀한다. 매트한 단색·뚜렷한 홀드 테두리·최소 44pt 백스텝과 안전영역 간격을 적용했다.
- **모션:** 발은 피격·더킹의 리그 이동/회전에서 보정하고 횡이동도 실제 이동 방향으로
  디딘다. 가드는 보간하며 백스텝은 0.18초의 뒷발→앞발 시각 동작으로 연결한다. 훅은
  접촉 뒤 안쪽으로 지나가고, 어퍼컷·바디도 별도 회수 경로를 거친다. 8종 모두 기존
  `activeStart`의 신전 정점과 원래 자세 복귀를 유지하며, 복서·링 지오메트리는 그대로다.

#### 확인된 결과와 남은 확인

- 실제 Swift 전투 코어를 렌더링·영속화 없이 실행해 방향별 관측, 기록 만료, 행동 마스크,
  고정 난수 재현, 입력 조합·방어 모션 수학 및 HP·스태미나·링 경계 불변식을 확인했다.
- 고정 봇 3종 × 시드 12개 × 라운드 1/200의 72개 대전 비교: 잽 반복 봇 상대 RIVAL
  승리 0/12→10/12, 혼합 공격 0/12→9/12, 한쪽 더킹·바디 반복 12/12→12/12다.
  모든 패턴에서 후반 RIVAL의 누적 이동량이 증가했다. 이는 같은 초기 조건의 자동 봇
  비교일 뿐, 200라운드 누적 플레이나 사람 상대 승률을 검증한 결과가 아니다.
- 초반의 한쪽 더킹·바디 반복 봇은 여전히 모두 패배했다. 따라서 “모든 초보자가 쉽게
  이긴다”거나 “숙련자도 이제 이긴다”고 주장하지 않으며 사용자의 초반/기존 후반 플레이
  피드백을 받아야 한다. 같은 패턴에 대한 대응이 읽히는지도 미확인이다.
- iPhone SDK 테스트 코드 컴파일을 확인했다. 실기기 설치·터치/햅틱/모션 확인, 전체
  iOS XCTest 실행, 장시간 발열·프레임 검증과 App Store 업로드는 이번에 하지 않았다.

- **예외:** 미래형 AI 대시보드·실전 `PATTERN DETECTED` 반복 알림·임의의 적응률 게이지는
  사용하지 않는다. 현재 적응 계수는 학습 정확도가 아니며 AI 읽기는 행동과 코너 리포트로 전달한다.
- **예외:** 저체력 이동 페널티·새 넉다운/기상 규칙·별도 라이벌 레벨/스타일은 단순 연출이
  아니라 전투 규칙 변경이므로 이번에 도입하지 않는다. 현재 4단계 회피와 강화된 속도를
  제안서의 예시 3단계·0.35배로 되돌리지 않는다.
- **접근성:** 실전의 동작 줄이기는 줌·흔들림·피격 섬광·잔상을 제거하고 짧은 문자·음향·
  햅틱을 남긴다. 카운터 기회의 손익이 달라지지 않도록 전투 속도와 유효 입력 시간은 유지한다.
  대기실 턴테이블에도 적용했으나 체육관 카메라 등 앱 전체의 모든 움직임까지 정리한 상태는 아니다.
- **보류:** 배경음 덕킹은 실제 배경 트랙 도입 뒤 검토한다. 완전 정지형 Hit Stop은
  카운터 창·탈진·입력 시간과의 관계를 먼저 검증한다. 화면 전환·분석 수치 애니메이션은
  이번 실전 피드백 묶음의 사용자 승인 후 별도 진행한다.

### 이번 변경에서 확인한 것

- iPhone 12 mini에서 최신 Debug 빌드를 서명, 설치, 실행했다.
- 실기기 UI 테스트로 앱 실행 전투 오프닝 프레임과 오프닝 종료 후 메인 메뉴 전환을
  각각 확인했다.
- 오프닝 캡처에서는 RIVAL의 크로스와 플레이어의 더킹이 동시에 읽히도록 대각선 카메라
  구도를 조정했다.
- 오프닝은 실제 전투 갱신과 분리되어 장기 습관, AI, 피해 판정을 변경하지 않는다.
- 플레이어의 정확한 더킹 뒤에는 짧은 슬로모션과 카메라 줌으로 기존 카운터 창을
  감각적으로 강조한다. 이 연출은 피해량이나 적응형 AI 규칙을 변경하지 않는다.
- 2026-09-07 iPhone 12 mini 단위 테스트 **61개**, 메뉴→경기·가로 조작부·KO→다음 라운드·
  동작 줄이기 UI 시나리오 **4개** 통과. 가로 조작부와 두 KO 결과 캡처를 직접 확인했다.
- Debug iPhone SDK 테스트 번들 및 Release iPhone SDK 빌드 성공. Release 번들은 로컬
  `du` 기준 약 5.5MiB이며, 다운로드 크기·프레임 성능 측정값은 아니다.
- 테스트 경기·승수는 실사용 저장소에서 격리했다. 구버전 JSON fixture의 복원을 검증했으나
  실제 스토어 설치본 위 모든 과거 버전의 업데이트 경로를 검증한 것은 아니다.

위 항목은 빌드와 자동화된 전환 검증의 결과다. 오프닝의 속도, 타격 리듬, 카메라 거리,
체육관의 실제 조작감과 장기 재방문 동기는 추가 플레이테스트가 있어야 검증된 플레이어
경험으로 표현할 수 있다.

### 코드 점검으로 확인한 다음 검증 항목 — 3차 적용 후 잔여

1. **공격의 시각 접촉과 자세 연결:** 2026-09-09 작업 트리에서는 8종 모두 `PunchMotion`의
  공통 시계로 기존 `activeStart`와 신전 정점을 맞추며, 비직선 펀치도 하체 회전·가드 복귀와
  거리 보정을 사용한다. 위 9월 7일 기록과 달리 나머지 6종의 시점 통합도 적용된 상태다.
  다만 목표 높이는 정해진 값이므로 실제 상대 자세별 접촉, 디딤발 접지, 피격·공격·가드
  전환은 별도 개선·검증 대상이다. 손맛 향상을 아직 실기기 관측 결과로 주장하지 않는다.
2. **이동 습관의 좌표계:** 2026-09-09 `sampleHabits`와 거리 차단의 재투영 오류를 수정하고
  상대 기준 입력을 그대로 사용한다. 네 방향 전진의 학습 결과 일치와 실행 불가능한 이동
  제외를 검사한다. 벽에서 실제로 움직이지 못한 입력을 변위 기반으로 걸러내는 후속은 남는다.
3. **카운터 경계:** 입력 예약 태그와 피해 배율의 조건이 각각 `pendingDodgeCounter`와
  `defender.exposed`다. 창 끝에서 시작하는 느린 펀치도 의도한 보너스를 받는지 별도 검증한다.
4. **후속 UX·운영:** HP 잔여 피해 레이어, 메인→실전 전환 단축, 장문/큰 글씨 결과 화면,
  체육관 소리 설정·시간 기록, Game Center 실패 경로, Release 장시간 발열·프레임 측정은
  각각 독립적인 완료 기준과 실기기 확인이 필요하다. 과거 Python 성능 수치를 iOS 근거로 쓰지 않는다.

### 다음 개선 목표

1. **전투 적응의 가시성:** RIVAL의 습관 대응이 자세, 거리, 가드, 공격 순서로 충분히
   읽히는지 실기기 플레이에서 확인하고, 필요할 때만 짧은 전술 유지 상태를 추가한다.
2. **프리미엄 UI의 일관성:** 공유 패널과 메뉴를 매트한 표면과 절제된 대비로 통일하되,
   실전 HUD와 터치 조작의 즉시성을 희생하지 않는다.
3. **보상 동기의 검증:** 코스튬 해금 조건이 반복 플레이의 목표로 작동하는지 확인하고,
   전투 성능 보상이나 숨은 난이도 보정으로 확대하지 않는다.
4. **온라인 기능의 준비:** App Store Connect에 `com.acertainromance401.pixelboxing.totalWins`
   리더보드를 만들고 실제 Game Center 제출과 실패 상태를 검증한다.
5. **단계적 확대:** 한 경험 영역을 수정한 뒤 iPhone 빌드와 사용자 플레이 피드백을
   확인하고, 승인 전에는 다음 대형 개선 범위를 시작하지 않는다.

## 15. 핵심 메시지

RIVAL은 플레이어를 수치적으로 강하게 만드는 게임이 아니라, 반복 습관을 읽는 적에게
대응하며 플레이어가 전략적으로 성장하는 게임이다. 적응형 AI, 스태미나, 방향 더킹,
카운터, 체육관, 나레이션, 라운드 통계와 코스튬 보상은 각각 독립 기능이 아니라 다음
경험을 만들기 위해 연결되어 있다.

> 적은 나의 반복을 읽고 성장한다. 나는 그 적과 싸우며 내 전략을 바꾼다. RIVAL은 그 상호 성장을 설명이 아니라 전투와 피드백의 체감으로 전달하는 게임이다.
