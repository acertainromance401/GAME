# RIVAL UI/UX 전면 재설계 제안

> **작성일:** 2026-11-08
>
> **상태:** 승인된 메인·스토리 선택·라커룸·실전 HUD·코너/결과와 보조 화면의 네이티브 UI 적용을 완료했다. 전투 조작 버튼의 기존 배치는 유지한다. 독립 시안, 실제 구현과 검증 범위는 아래 기록에서 구분한다. RIVAL은 핵심 경험, 스토리는 선택형 프리미엄 콘텐츠로 표현한다.
>
> **대상:** iOS RIVAL의 가로 화면 UI/UX. 기존 UI를 부분적으로 다듬는 작업이 아니라 화면 구성, 탐색 구조, 시각 언어와 인터랙션을 다시 설계한다.
>
> **확인된 범위:** 게임 장면·자산·컷씬은 그대로 보존한다. 인게임 HUD·조작 버튼·코너 및 결과 UI의 외형은 재설계할 수 있지만, 캐릭터·맵·복장 디자인과 기존 포즈·모션·카메라·조명·전투 동작은 변경하지 않는다.
>
> **표현용 재사용:** UI 표현에 필요하면 기존 실제 캐릭터 모델을 직접 재사용해 별도 초상·렌더 이미지·화면 구성 요소로 활용할 수 있다. 모델을 사용하는 것과 원본 모델 디자인이나 실제 게임 장면을 수정하는 것은 구분한다.
>
> **정본:** [RIVAL 게임 의도와 설계 철학](./RIVAL_GAME_INTENT_AND_DESIGN_PHILOSOPHY.md). 현재 구현과 과거 검증은 [iOS README](../../ios-pixel-boxing/README.md)를 따른다. 이 문서의 제안을 현재 기능이나 검증된 성과로 해석하지 않는다.

## 1. 제안의 핵심

**복싱 클럽에서 경기를 준비하고, 링에 올라가며, 코너에서 다음 전략을 생각하는 경험을 만든다.**

현재의 검은 배경, 테두리 버튼, 좌우 분할을 유지한 채 색상과 간격만 바꾸는 접근을 중단한다. 공간마다 목적을 부여하되, 하나의 브랜드와 조작 체계로 연결한다.

| 공간 | 전달하려는 경험 | 중심 내용 |
| --- | --- | --- |
| 메인 | 경기를 앞둔 긴장감 | 기다리는 상대, 현재 경기, 경기 시작 |
| 스토리 | 다음 상대를 선택하는 과정 | 대진, 진행 상태, 상대 성향과 접근 조건 |
| 대기실 | 선수 준비 | 실제 복서, 스타일·복장·자세, 착용과 미리보기 |
| 실전 | 복싱 중계와 즉각적인 조작 | 두 복서, 거리와 움직임, 필수 HUD와 전투 조작 |
| 코너·결과 | 다음 전략을 세우는 시간 | 승패, 주요 경기 기록, 실제 RIVAL 대응과 다음 행동 |

추천 방향은 **어두운 경기장과 밝은 선수 준비·기록 공간의 대비를 가진 복싱 클럽**이다. 모든 화면에 같은 검은 카드와 동일한 헤더 구조를 반복하지 않는다.

### 제품 포지셔닝과 명칭

- **RIVAL 대전은 게임의 핵심 경험**이다. 가격 등급이나 체험판처럼 표현하지 않는다.
- **스토리는 선택형 프리미엄 콘텐츠**다. RIVAL을 "무료 플레이", "FREE PLAY", "無料プレイ"로 부르고 스토리와 가격으로 대비하는 문구는 사용하지 않는다.
- 상대를 읽고 전략을 바꾸는 경험, 경기·기록·보상으로 RIVAL의 가치를 전달한다.
- 실제 가격·구매·복원·진행 조건은 해당 화면에서 정확하게 안내한다. 명칭 변경은 가격·이용권·보상 규칙 변경이나 App Store 반영 완료를 뜻하지 않는다.

### MCP 자료의 한계

복싱 시안은 정적인 SVG 기반 웹 예시이며, 실제 선수 사진이나 네이티브 게임 화면이 아니다. 효과 갤러리 역시 웹 시연이고, 일부 추가 효과는 문서 설명만 존재한다. 범용 패턴은 설계 지침이며 완성된 SwiftUI 컴포넌트나 실기기 검증 결과가 아니다.

따라서 다음 원칙으로 적용한다.

- 세로 포스터를 가로 앱 화면에 그대로 붙이지 않는다. 구도와 색의 역할을 조작 화면에 맞춰 다시 설계한다.
- 원본 사진·로고·문구를 복제하지 않고, 승인된 실제 게임 캐릭터와 링 자산을 재사용한다.
- 효과가 레퍼런스에 있다는 이유만으로 사용하지 않는다.
- 웹 예제의 구현·성능·접근성을 네이티브 앱에서 검증된 것으로 취급하지 않는다.
- 기존 제작 포스터의 앱 리소스 추가나 새 포스터 제작은 별도 승인 범위로 둔다.

## 3. 시각 언어

### 공간별 표면과 색

아래 표면·색 제안은 UI 배경과 패널에 적용한다. 기존 3D 장면의 조명·재질·색상이나 캐릭터·맵·복장 디자인을 바꾸는 제안이 아니다.

- **경기 공간:** 깊은 차콜과 청회색. 복서와 경기 정보에 대비를 집중한다.
- **준비·기록 공간:** 따뜻한 회백색과 낮은 채도의 중성 표면.
- **청색·적색:** 선수 구분과 전투 행동에 의미 있게 사용한다.
- **금색:** 실제 획득 보상에만 제한적으로 사용한다.

두 종류의 공간은 글자 체계, 정렬, 아이콘 의미, 행동 우선순위와 상태 표현을 공유한다. 서로 다른 앱처럼 보이는 테마 교체가 아니라, 같은 복싱 클럽 안에서 장소가 바뀌는 느낌을 목표로 한다. 정확한 색상 값과 대비는 시안 단계에서 확정·검증한다.

### 조판과 정보 위계

- 큰 글자는 경기명·결과처럼 중요한 순간에만 사용한다.
- 브랜드명 외의 플레이어용 제목과 행동은 현지화한다. 작은 영문 장식으로 정보를 대체하지 않는다.
- 본문·제목·수치·캡션의 역할을 나누고, 숫자는 비교하기 쉽게 정렬한다.
- 큰 글씨에서 필수 내용을 축소하거나 잘라 해결하지 않고, 줄바꿈·재배치·스크롤 정책을 설계한다.

### 선택 표현: 현재 대상이 명확한 상태

레트로 메뉴에서 참고할 것은 특정 색이나 질감이 아니라 **어떤 항목이 선택됐는지 즉시 알 수 있는 원리**다.

- 상대·탭·장비의 선택은 매트한 표면 대비, 글자 무게와 선택 표시로 일관되게 표현한다. 색만으로 구분하지 않는다.
- 선택·착용·미리보기·잠김은 서로 다른 상태다. 선택 강조를 착용 성공이나 도전 가능 상태처럼 보이게 하지 않는다.
- 터치와 이전·다음 버튼, 접근성 탐색에서도 같은 선택 대상과 상태를 전달한다.

### 제외할 표현

- 내용마다 반복되는 테두리 박스와 동일한 카드 묶음
- 장식용 좌측 세로줄, 대각선 화살표, 가짜 배지·바코드
- 전 화면의 과도한 글로우·유리 효과·리플·틸트·패럴랙스
- 모든 화면을 거대한 타이포와 올블랙 배경으로 바꾸는 대체 템플릿
- 실전 조작부의 색상 그라데이션

실제 선택·입력·상태 구분에 필요한 표면과 테두리는 유지할 수 있다.

## 4. 화면별 전면 재구성

### 4.1 메인: 기존 좌우 분할 폐기

현재 [메인 메뉴](../../ios-pixel-boxing/PixelBoxingIOS/MainMenuView.swift)의 왼쪽 메뉴 목록과 오른쪽 캐릭터 박스 구조를 교체한다.

새 구성의 제안:

1. 화면 중심에 박스에 갇히지 않은 실제 복서와 경기장 장면을 둔다.
2. 상단에는 작은 RIVAL 브랜드와 기록·설정 진입을 배치한다.
3. 아래에는 현재 경기 정보와 `경기 시작`을 묶은 하나의 경기 안내 영역을 둔다.
4. 최하단에는 `경기 · 스토리 · 대기실 · 체육관` 목적지 내비게이션을 둔다.

기존 캐릭터 장면을 둘러싼 UI 배치를 재구성하거나, 실제 복서 모델을 직접 재사용한 UI용 표현을 활용할 수 있다. 현재 캐릭터 화면을 그대로 배치하는 방식으로만 제한하지 않는다. 복서 외형, 원래 메인 메뉴 대기 포즈·모션과 기존 카메라·조명 설정은 유지한다.

추가 참조의 **장면 중심 메뉴** 원리를 반영한다. 복서·링 또는 별도 UI용 캐릭터 비주얼에 넓은 영역을 주고, 경기 정보·경기 시작·탐색을 구분해 배치한다. 캐릭터와 경기명을 함께 편집할 수 있지만, 얼굴·글러브나 필수 행동을 장식 글자로 가리지 않는다. 포스터의 거친 효과나 큰 영문 제목을 그대로 이식하지 않는다.

메뉴 목록을 먼저 읽게 하는 대신, **상대가 기다리고 있고 경기에 들어갈 수 있다는 인상**을 목표로 한다. 거대한 제목과 여러 버튼으로 공간을 채우지 않는다. 새로하기 같은 위험한 행동은 주 행동과 분리한다.

목적지 내비게이션과 `경기 시작` 같은 실행 행동을 혼동하지 않게 한다. 실전 중에는 메인 탐색 구조가 전투 시야나 조작부를 점유하지 않는다.

### 4.2 스토리: 대진 중심 선택 화면

현재 [스토리 선택](../../ios-pixel-boxing/PixelBoxingIOS/StoryViews.swift)의 세로 목록과 설명 패널을 대진 중심 구성으로 바꾼다.

- 선택 상대의 큰 비주얼과 하단의 가로 초상 탐색을 연결한다. 가로 탐색에는 이전·다음 버튼도 제공한다.
- 선택한 상대를 중심에 두고 이름·라운드·복싱 성향을 표시한다.
- 큰 비주얼·선택 초상·이름·진행 상태·도전 행동은 같은 상대 ID를 기준으로 함께 갱신한다. 애니메이션 때문에 이전 상대의 정보나 버튼 조건이 남지 않게 한다.
- 실제 진행 순서와 클리어 상태를 함께 보여준다.
- 코너 조언과 보상은 짧은 요약을 먼저 제공하고, 자세한 내용은 펼쳐 확인한다.
- `도전 가능 · 진행 필요 · 이용권 필요`를 서로 다른 상태로 표현한다.
- 선택한 상대의 이름이나 작은 초상이 준비 화면으로 이어지도록 연속성 전환을 검토한다.
- 상대 초상이나 대진의 시각 요소에는 해당 상대의 실제 캐릭터 모델을 직접 재사용할 수 있다.

콘솔 홈 대표 프레임의 **선택한 콘텐츠가 주 비주얼을 결정하는 관계**를 스토리 탐색에 반영한다. 같은 상대의 식별 가능한 초상과 이름을 준비 화면까지 유지한다. 작은 TV용 타일을 그대로 옮기지 않고 iPhone의 터치 영역·큰 글씨·진행 안내에 맞춰 다시 배치한다.

스와이프만으로 기능에 접근하게 하지 않는다. 화면을 바꾸기 위해 3D 렌더러 두 개를 복제하거나, 애니메이션 완료까지 입력을 잠그지 않는다. 기존 이어하기·재도전·장면 다시 보기와 접근 조건은 새 화면에서도 접근할 수 있어야 한다.

#### 추가 제안: 스토리 상대 캐릭터 단체 샷

사용자가 추가한 [ULF Esports 단체 포스터 레퍼런스](https://www.pinterest.com/pin/1139551511996598144/)를 참고한다. 중앙의 주요 인물을 크게, 주변 인물을 좌우·뒤쪽에 배치한 단체 구도와 깊이를 실제 RIVAL 상대 모델로 해석한다. 이는 MCP 예시가 아니라 사용자가 제공한 추가 참조다.

**역할과 구도**

- 스토리 상대 선택 화면의 대표 비주얼로 우선 검토한다. 다음에 마주할 상대들이 한 세계에 속한다는 인상을 전달한다.
- RIVAL을 중심에 두고 다른 상대를 좌우·앞뒤로 배치하는 구도를 검토한다. 동일 크기 초상을 일렬로 나열하는 대신, 기존 외형·복장·자세의 특징으로 각 상대를 구분한다.
- 등장 인물은 [실제 스토리 상대 정의](../../ios-pixel-boxing/PixelBoxingIOS/StoryMode.swift)와 [상대 선택 목록](../../ios-pixel-boxing/PixelBoxingIOS/StoryViews.swift)을 기준으로 확정한다. 레퍼런스의 인원수나 예전 대진 구성에 맞춰 임의로 캐릭터를 추가·제외하지 않는다.
- 세로 포스터를 그대로 잘라 붙이지 않고, 가로 앱 화면용 구도를 따로 설계한다. 상대 이름·진행 상태·선택 도구·도전 버튼의 공간을 확보한다.
- 상대를 선택하면 해당 상대의 개별 정보와 준비 화면으로 이어진다. 단체 이미지 속 인물을 누르는 방식만 제공하지 않고 기존 선택 기능의 접근 가능한 대안을 유지한다.
- 단체 샷은 전체 라인업, 개별 비주얼은 현재 선택 상대를 전달한다. 두 큰 이미지를 한 화면에 경쟁시키지 않으며, 둘의 관계와 가로 초상 탐색을 다섯 화면 시안에서 함께 검토한다. 불필요한 별도 소개·로딩 화면은 추가하지 않는다.
- 메인 화면의 스토리 진입 영역에 일부를 재사용하는 것은 후속 검토 사항이다. 모든 화면에 같은 단체 샷을 반복하지 않는다.

**제작·보존 조건**

- 실제 게임 모델 또는 모델 생성 구조를 직접 재사용한 UI용 별도 렌더를 우선 검토한다. 정적인 비주얼을 위해 여러 복서의 실시간 3D 렌더러를 상시 실행하지 않는다.
- 원본 사진·선수·로고·문구는 복제하지 않는다. 붉은 연기·바위·깃발을 그대로 이식하지 않고 단체 구도·시각 위계·실루엣 분리의 원리만 참고한다.
- UI용 표현은 실제 전투·컷씬의 노드·상태·카메라·조명과 분리한다. 캐릭터·복장 디자인, 원래 메뉴 대기 모션과 기존 게임 장면은 변경하지 않는다.
- 단체 샷에 상대가 보인다고 해서 도전·구매·해금 조건이 바뀌지 않는다. 실제 상태 안내와 버튼 조건을 유지한다.
- 작은 화면과 큰 글씨에서는 대표 비주얼을 축소하거나 생략해 정보와 주 행동을 우선한다.

현재는 추가 디자인 아이디어이며, 단체 샷의 최종 구도·제작·앱 적용은 아직 완료되지 않았다. 기존 포스터 통합이나 새 컷씬 제작을 승인한 것으로 해석하지 않는다.

### 4.3 대기실: 선수 준비 공간

현재 [대기실](../../ios-pixel-boxing/PixelBoxingIOS/GameView.swift)의 검은 카드 목록에서 벗어나 실제 선수와 선택 도구를 중심에 둔다.

- 따뜻한 회백색 또는 낮은 채도의 중성 배경을 사용한다.
- 중앙 복서를 중심으로 스타일·복장·자세 선택 도구를 배치한다.
- 복장은 긴 설명 목록 대신 작은 시각 견본과 이름으로 탐색한다.
- 선택한 항목의 설명과 획득 조건에 정보를 집중한다.
- 현재 착용 중인 항목과 미리보는 항목을 지속적으로 구분한다.
- 선택한 견본은 공용 선택 표현으로 강조하되, 착용·미리보기 문구와 획득 조건을 함께 유지한다.
- 기존 스토리 보상·외형·벨트의 접근 경로와 획득 조건을 새 분류 안에서도 유지한다.

잠금 복장은 미리볼 수 있지만 착용한 것처럼 표현하지 않는다. 소유한 복장을 누르면 바로 착용하는 현재 규칙을 유지한다. 새 확인 버튼이나 취소에 의한 장비 롤백을 임의로 도입하지 않는다.

복장 선택 도구와 설명의 디자인만 바꾼다. 기존 복장·글러브·벨트 등의 외형·색·재질을 수정하거나 새 장비 디자인을 제작하지 않는다.

선수와 장비 미리보기의 표현에는 실제 캐릭터 모델과 기존 장비를 직접 재사용할 수 있다. 일반적인 복서 그림으로 대체하거나 원본 장비 디자인을 바꾸는 방식이 아니다.

### 4.4 실전: 복싱 조작판과 중계형 HUD

변경 대상은 기존 게임 장면 위의 HUD와 조작 버튼 UI다. 게임 장면, 캐릭터·맵·복장, 카메라·조명, 전투 모션과 타격 연출은 그대로 유지한다.

**HUD**

- 상단 가장자리에 얇고 선명한 양측 체력·스태미나를 배치한다.
- 중앙에는 라운드와 시간을 둔다.
- 넓은 검은 박스 대신 필요한 정보에만 작은 불투명 받침을 사용한다.
- 두 복서 사이의 시야를 비워두고 나레이터 박스를 다시 넣지 않는다.

**조작부**

- 왼쪽을 이동·방어 영역, 오른쪽을 공격 영역으로 시각적으로 묶는다.
- **후속 사용자 제한:** 버튼 디자인과 눌림 피드백만 바꾸고 배치는 바꾸지 않는다. 왼쪽의 기존 3×3 이동·위빙·가드·더킹 패드와 오른쪽 상단 백스텝·하단 잽/크로스의 위치·순서·크기·간격을 유지한다. 시안의 단순화된 조작 배치를 그대로 옮기지 않는다.
- 공격·방어·조합·잠김 상태를 모양·명암·라벨로 구분한다.
- 모든 버튼에 같은 크기와 같은 테두리를 적용하지 않는다.
- 표시와 정보 위계는 교체하되 현재 공격 발동 시점, 홀드와 해제 동작을 유지한다.

새 조이스틱이나 스와이프 전투 조작은 디자인 교체와 분리한 별도의 조작 실험이다. 실시간 HUD 수치를 모션 완료까지 늦추거나, 조작 타이밍을 연출에 종속시키지 않는다.

### 4.5 코너·결과: 하나의 경기 기록지

빈티지 레퍼런스를 승패 팝업이 아니라 잘 편집된 코너 기록지로 해석한다.

- 종이색 바탕에 결과와 점수를 명확히 표시한다.
- 양측 주요 공격·회피를 정렬한 간결한 기록을 제공한다.
- 실제 감지된 RIVAL 대응을 짧은 코너 조언으로 표시한다.
- 다음 라운드·재도전·나가기는 하단의 명확한 행동 영역에 둔다.
- 통계마다 별도 카드를 만들지 않는다.

데이터가 없을 때 그럴듯한 분석 문구를 만들지 않는다. 기존 KO 모션·연출, 결과 공개 시점과 다음 행동의 활성화 조건을 유지한다. 결과 기록지의 UI 변경을 승리·엔딩 컷씬 변경으로 확대하지 않는다.

### 4.6 설정·구매·보조 화면

주요 화면과 같은 글자·표면·행동 체계를 사용한다. 설정, 기록과 구매를 시각적으로 정리하더라도 기존 기능의 접근 경로를 빠뜨리지 않는다.

특히 구매·복원·권한 확인·오류·취소는 외형이 아니라 실제 상태에 따라 표현한다. 디자인 교체를 이유로 상품·가격·해금 규칙이나 거래 동작을 변경하지 않는다.

## 5. 모션 체계

| 상황 | 제안하는 역할 | 지켜야 할 조건 |
| --- | --- | --- |
| 눌림 | 짧고 즉각적인 조작 피드백 | 시각 변화가 터치 영역을 줄이거나 동작을 지연시키지 않음 |
| 상대 선택 | 선택 대상과 다음 화면의 관계 설명 | 안정적인 대상 ID, 직접 진입·취소·연속 선택 지원 |
| 화면 이동 | 이동 방향과 목적 설명 | 과한 거리·회전·상시 움직임 제외 |
| 장비 변경 | 실제 선택·미리보기·착용 상태 확인 | 미획득 항목을 착용 성공처럼 표현하지 않음 |
| 결과 공개 | 전투 종료와 다음 행동 연결 | 기존 KO 공개 시점 이후에 표시 |
| 동작 줄이기 | 움직임 없이 기능과 상태 전달 | 이동·확대를 제외하고 정보와 조작 유지 |

MCP 갤러리에서 효과를 많이 가져오는 것이 목표가 아니다. 선택·이동·상태 확인에 필요한 효과만 사용한다. 숨겨진 복제 요소가 접근성 트리에 남거나 이중 포커스를 만들지 않게 한다.

여기서 모션은 UI의 눌림·선택·전환 피드백을 뜻한다. 기존 캐릭터 애니메이션, 컷씬 안무·길이, 카메라 움직임과 타격 연출을 다시 만드는 범위는 아니다.

## 6. 구현 접근

[UIStyleKit.swift](../../ios-pixel-boxing/PixelBoxingIOS/UIStyleKit.swift)의 색상 상수와 modifier만 교체하는 작업으로 끝내지 않는다.

- 화면 구성과 탐색 소유권을 먼저 재설계한다.
- 원시 팔레트·간격·글자 값과 배경·행동·선택·오류 같은 의미별 토큰을 구분한다.
- 각 화면과 공용 컴포넌트의 정상·눌림·선택·잠김·비활성·로딩·실패 상태를 연결한다.
- 기존 컨트롤러·전투·진행·구매 로직과 새 UI의 연결을 확인한다.
- 디자인 토큰을 도입한 뒤에도 호출부에 임의 값이 남아 체계가 무력화되지 않게 한다.

**UI 표현을 위한 실제 캐릭터 모델 재사용: 허용**

- 기존 게임의 실제 모델 또는 모델 생성 구조를 재사용해 UI용 인스턴스·초상·렌더 이미지를 만들 수 있다.
- 메인의 캐릭터 표현, 스토리 상대 초상·대진·단체 샷, 대기실 선수·장비 미리보기 등에 목적에 맞게 활용한다. 모든 화면에 장식으로 반복 배치하는 것이 목표는 아니다.
- UI용 표현은 실제 전투·컷씬의 노드와 상태를 변경하지 않도록 분리한다. 원본 캐릭터와 복장 디자인은 유지한다.
- 구체적인 UI용 구도와 표현 방식은 화면 시안에서 제시·확정한다. 기존 게임 장면을 수정하거나 보존 대상인 원래 메뉴 대기 모션을 교체하는 승인으로 해석하지 않는다.
- 전경 강조·크롭·인물과 정보면의 레이어 관계는 별도 UI용 자산 안에서 검토한다. 실제 게임 카메라·장면이나 원본 모델의 형태를 바꾸어 같은 효과를 만들지 않는다.
- UI용 모델 재사용은 이미 제작한 포스터의 앱 통합이나 별도 포스터 제작과 구분한다.

## 8. 진행 순서와 승인 지점

3. **디자인 승인:** 추천 방향, 세부 시안, 상태 표현과 구현 범위를 사용자와 확정한다.

## 10. 현재 결정 상태

- **확인된 요청:** 기존 디자인을 전면 교체해도 되며, MCP 참고 내용을 바탕으로 먼저 방향을 제안한다.
- **확인된 변경 경계:** 게임 장면·자산·컷씬과 기존 포즈·모션·카메라·조명·전투 동작은 보존한다. 인게임 HUD·조작 버튼·코너 및 결과 UI의 외형은 재설계할 수 있다.
- **확인된 표현 허용:** 기존 실제 캐릭터 모델을 UI 표현에 직접 재사용할 수 있다. 원본 모델 디자인·게임 장면의 수정과는 구분하며, 구체적인 활용 방식은 화면 시안에서 정한다.
- **추가된 사용자 아이디어:** 현재 스토리의 7개 대결 정의에 대응하는 원본 외형으로 독립 단체 샷을 제작해 스토리 시안과 첫 네이티브 묶음에 사용했다. 첫 스파링과 마지막 대결은 각각 RIVAL의 해당 모습이며 7명의 별개 인물이라는 뜻이 아니다.
- **추가 레퍼런스 선별 반영:** 장면 중심 메인, 선택 상대에 연동되는 큰 비주얼·가로 탐색, 일관된 초상·이름, 명료한 선택 상태와 제한적인 UI용 전경 표현을 제안에 반영했다. 원본 스타일 전체와 직접 확인하지 않은 영상 모션은 채택하지 않았다.
- **추천안:** 어두운 경기장과 밝은 선수 준비·기록 공간이 연결되는 복싱 클럽 방향.
- **후속 승인:** 사용자는 다섯 화면의 전체 방향을 승인하고 메인 랭킹 진입과 더 자연스러운 복싱 문구·서체를 요청했다. 실전 적용 중에는 전투 버튼 배치를 바꾸지 않는다는 제한을 추가했다. 이후 남은 코너·결과와 보조 화면을 전부 마무리하도록 요청해, 별도 중간 승인 대기 없이 마지막 묶음을 구현·검증했다.
- **문서화 당시와 후속 실행의 구분:** 최초 제안, 독립 시안과 단계별 네이티브 적용을 아래 기록에서 분리한다. 현재 승인된 UI 범위의 구현은 완료됐지만 시안의 모든 배치를 그대로 이식한 것은 아니며, 실계정 결제·전체 회귀·스토어 배포 완료를 뜻하지 않는다.

## 11. 2026-11-08 실행 결과와 검증 범위

### 제작한 산출물

- 메인·스토리 상대 선택·대기실·실전 HUD·코너 결과의 다섯 연결 화면과 선택 상대 상태를 제작했다.
- 한국어·영어·일본어 시안, 직접 조작 가능한 독립 프로토타입, 14초 흐름 시연을 만들었다.
- 실제 SceneKit 모델과 원본 장면으로 27개 렌더 이미지를 만들었다. 초상·복장·스타일 미리보기와 단체 샷은 별도 UI용 인스턴스이며 원본 모델 디자인을 수정하지 않았다.
- 스토리 시안은 현재 `StoryOpponent.allCases`의 **7개 정의**를 기준으로 한다. 과거 제출·출시 문서의 5명 구성 기재를 현재 상대 수로 사용하지 않았으며, 과거 기록을 소급 변경하지 않았다.
- 프로토타입의 진행·장비·경기 기록은 명시된 예시다. 실제 전투 판정·습관 저장·보상·구매·복원·권한 확인을 실행하지 않는다. 잠긴 복장 선택은 미리보기일 뿐 착용 성공이 아니다.
- 화면 페이드 300ms, 상대·복장 시각 피드백 200ms, 눌림 피드백 120ms를 시안에서 사용했다. 조작 대상은 이동·축소하지 않으며 시스템 동작 줄이기를 임의로 해제하지 않는다. 기존 메뉴 대기 모션을 새 모션으로 교체하지 않았다.

- 격리된 원본 모델 캡처·브랜딩 검사 3개, 실패 0개. 실제 27개 PNG와 상대 명칭·라운드 데이터를 출력했다.

- 다섯 화면, 선택 상대 상태, 영어·일본어 및 작은 화면·큰 글씨 렌더를 별도로 확인했다. 시연 파일은 실제 프로토타입을 녹화한 956×440·14초·140프레임 영상이다.
- 실제 경기장·전투·입력·컨트롤러·복싱 모션·포즈 소스 6개의 작업 전후 해시가 동일함을 확인했다. 메뉴 대기 모션·맵·VS 소스는 작업 전 격리 사본과 별도로 대조했다.

### 미확인 사항과 다음 승인 지점

- 144개 검사는 브라우저 프로토타입 검사이며 네이티브 iPhone 플레이 검증이 아니다. 물리 기기는 설치·실행까지 확인했지만 Xcode UI 테스트 대상으로 열거되지 않아 실기기 UI 자동 검사와 직접 터치·햅틱 관찰은 하지 못했다.
- 전면 네이티브 UI의 실전 입력·조합·KO 공개·저장·거래·장기 플레이 영향과 전체 회귀 성공을 검증했다는 뜻이 아니다. 기존에 별도로 확인된 전체 회귀 실패를 이번 검사의 성공으로 덮지 않는다.
- 당시 다음 단계였던 메인·상대 선택의 실제 적용과 후속 검증은 아래 12절에 기록한다.

## 12. 승인 이후 첫 네이티브 적용: 메인·스토리 선택

### 실제 반영

- [메인](../../ios-pixel-boxing/PixelBoxingIOS/MainMenuView.swift)은 중앙의 기존 라이브 복서, 상단 랭킹·코너 노트·새 대전·설정, 하단 경기 시작과 RIVAL·스토리·라커룸·체육관 탐색으로 교체했다.
- 랭킹은 기존 [Game Center 화면](../../ios-pixel-boxing/PixelBoxingIOS/LeaderboardView.swift)에 연결한다. 인증·오류·빈 목록 처리를 유지하며 가짜 순위나 선수 데이터를 추가하지 않았다.
- [스토리 선택](../../ios-pixel-boxing/PixelBoxingIOS/StoryViews.swift)은 단체 샷·선택 초상·가로 대진 탐색을 사용한다. 승인된 독립 렌더 16개만 [앱 이미지 리소스](../../ios-pixel-boxing/PixelBoxingIOS/Assets.xcassets)에 추가했다. 기존 제작 포스터는 적용하지 않았다.
- 실제 진행·이용권·잠금·이어하기·재대결·새 경기 준비·컷씬 다시 보기와 준비 취소 후 선택을 유지한다. 큰 접근성 글씨에서는 이미지 대신 스크롤 가능한 상대 목록을 사용하고 닫기·경기 준비 행동을 별도로 남긴다.
- [공통 제목·버튼](../../ios-pixel-boxing/PixelBoxingIOS/RivalMenuComponents.swift)은 기본 시스템 서체의 중간 굵기를 사용한다. RIVAL 워드마크는 유지하지만 제목의 과한 압축·최대 굵기와 작은 장식 자간을 줄였다.
- [한·영·일 문구](../../ios-pixel-boxing/PixelBoxingIOS/Localization.swift)는 `다시 링으로`, `경기 시작`, `대진표`, `코너 노트`처럼 경기 중심으로 다듬었다. `잽이 읽혔다면, 이번엔 바디로`는 조건부 조언이지 실제 관측 결과라는 주장이 아니다.
- 코너 노트는 실제 공격·회피와 확정 전술 읽기를 남기고 개발용 읽기 신뢰도·적응 계수 %를 표시하지 않는다. 초기화 안내는 지워지는 습관·대전 점수를 명확하게 설명한다.
- 독립 프로토타입에도 랭킹 진입과 문구·서체 수정을 반영했다. 프로토타입 랭킹은 실제 서비스에 연결됐다고 가장하지 않고 앱의 Game Center 진입 설명을 연다.

### 검증과 제한

- 최종 원본 프로젝트 집중 검사 **12개: 단위 11개 + 세 언어 메인 UI 1개**, 실패 0개.
- 최종 **실제 iPhone 12 mini UI 검사 3개**, 실패 0개. 한·영·일 랭킹 진입·7개 상대 선택·큰 글씨·모달 닫기·잠긴 복장 미리보기·체육관 왕복을 검사하고 실제 화면 캡처를 확인했다. 직전 실기기 준비 취소·선택 유지 검사도 통과했다.
- 넓은 시뮬레이터의 확장 검사에서 7개 UI 검사가 통과했다. 체육관 왕복 검사 1개는 `AVAudioEngine` 해제 중 시뮬레이터 오디오 RPC 시간 초과로 앱이 종료됐고, 같은 검사 단독 재실행과 최종 실기기 검사에서는 통과했다. 오디오 소스는 수정하지 않았다.
- 작은 iPhone 12 mini 시뮬레이터에서 3개 언어·큰 글씨·스토리 준비·랭킹 집중 UI 검사 4개가 통과했다. 이후 얼굴 가림·단체 샷 배치와 영문 대소문자의 마지막 보정은 최종 실기기 검사에서 확인했다.
- 서명된 iPhone SDK 빌드 성공. 실제 경기장·전투·입력·컨트롤러·포즈·모션·스토리 진행·구매·맵·VS 소스 10개의 작업 전후 해시와 원래 `MenuIdleMotion` 본문이 동일하다. 카메라·조명 대신 UI 표시 영역의 크기와 위치만 조정했다.
- 프로토타입의 144개 화면·언어·글씨·가로 크기 조합을 다시 검사했다. 랭킹 설명 열기·닫기와 포커스 복원도 검사한다. 브라우저 검사와 네이티브 검사를 서로 대체하지 않는다.
- 실기기 자동 터치·화면 캡처는 확인했지만 사람이 직접 느끼는 햅틱, 모션 감각, 실제 경기 몰입과 장기 플레이 영향은 확인하지 않았다. Game Center의 실제 서버 순위 정확성·실결제·복원·전체 회귀 성공·배포를 새로 검증한 것은 아니다.
- 테스트는 기존 비저장 메뉴 fixture를 사용했다. 실기기는 이후 별도 언어·fixture 인자 없이 정상 앱으로 다시 실행했다.

### 다음 묶음

이번 메인·스토리 선택에 대한 플레이 피드백 후 밝은 라커룸·기록 공간과 실전 HUD·결과 화면의 본격 레이아웃 교체를 진행한다. 기존 모델·복장·맵·컷씬·원래 메뉴 대기 모션·게임 규칙의 보존 조건은 계속 유지한다.

### 후속 피드백: 스토리 목록을 하단으로 이동

- 사용자가 선수 목록이 화면 중앙을 차지한다고 지적해, 컷씬 다시보기 버튼을 상단 헤더로 옮기고 가로 선수 목록을 경기 준비 버튼 바로 위에 붙였다. 하단의 별도 진행·다시보기 행은 제거하고 진행 표시는 상대 설명 영역으로 옮겼다.
- 기존 단체 샷은 유지한다. 선택 선수 초상은 상단 조작부와 머리가 겹치지 않도록 독립 UI 표시 위치·크기만 보정했다. 다시보기의 이용권·진행·장면 존재 조건과 콜백, 컷씬 내용·재생 로직은 변경하지 않았다.
- 큰 글씨의 세로 상대 목록·닫기·경기 준비도 유지한다. 다시보기 아이콘은 크기를 고정하되 44×44 이상 조작 영역과 현지화된 접근성 이름을 남겼다.
- 최종 실기기 집중 UI 검사 3개가 통과했다. 한·영·일의 위쪽 다시보기·아래쪽 목록 순서, 목록과 경기 준비 사이의 접근성 프레임 간격 16pt 이하, 두 실제 컷씬의 열기·닫기, 선택·준비 취소·큰 글씨를 검사했다. 상단 조작부가 화면 안에 완전히 들어오는지 추가 실기기 재검사도 통과했다.
- 넓은 시뮬레이터의 동일 배치·두 컷씬 검사 1개와 서명된 iPhone SDK 빌드가 통과했다. 독립 프로토타입의 144개 조합과 위쪽 다시보기 설명·포커스 복원도 재검사하고 갤러리·한영일 이미지·시연·오프라인 묶음을 갱신했다. 프로토타입에서는 실제 컷씬을 재생한다고 표시하지 않는다.
- 최초 새 UI 검사의 12pt 간격 가정은 영어 화면의 14pt 접근성 간격에서 실패했다. 목록이 준비 버튼에 인접한다는 요구는 16pt 이하로 검사하며, 아래에 재생 행이 남는 이전 배치는 이 검사에 통과하지 않는다. 초기 실패를 최종 성공 기록으로 대체하거나 숨기지 않는다.
- 진행·구매 소스의 작업 전후 해시는 동일하다. 경기장 소스에서는 작업 중 별도의 사우스포 모델 변경을 감지했으며 이 배치 작업은 해당 변경을 수정하거나 되돌리지 않았다. 따라서 이번 작업 전체에 대해 경기장 소스까지 작업 전후 동일하다고 주장하지 않는다. 기존 승인 UI 이미지를 새 모델로 재제작하는 작업도 포함하지 않았다.

## 13. 후속 네이티브 적용: 라커룸·경기 준비

### 실제 반영

- [라커룸](../../ios-pixel-boxing/PixelBoxingIOS/GameView.swift)을 따뜻한 종이색 바탕·짙은 글자와 실제 라이브 복서, 스타일·복장·자세·스토리의 네 탭으로 교체했다. 기본 화면은 왼쪽 선수와 오른쪽 선택 도구, 아래 닫기·경기 시작 행동을 사용한다.
- 실제 원본 모델로 복장 12개·스타일 3개의 장비 견본을 만들고 [앱 이미지 리소스](../../ios-pixel-boxing/PixelBoxingIOS/Assets.xcassets)에 추가했다. 일반 복장과 스토리 시작·최종 챔피언 복장을 빠뜨리거나 다른 그림으로 대체하지 않았다. 런타임에 견본마다 별도 SceneKit 렌더러를 띄우지 않는다.
- 소유한 장비는 선택 즉시 착용하고, 잠긴 복장·외형·자세는 미리보기로 구분하는 기존 규칙을 유지한다. 메인의 `준비 완료`는 닫기·이동 행동이지 새로운 장비 확정 버튼이 아니다. 닫기로 장비를 되돌리거나 잠긴 미리보기를 착용시키지 않는다. 스토리의 `경기 시작`은 기존 준비 콜백에 연결한다.
- 이용권·상대 승리·챔피언 벨트·자세 해금과 실제 구매 화면의 조건을 유지한다. 구매 화면이 열리면 아래 준비 화면의 조작·접근성 요소를 제거해 두 화면이 동시에 조작되지 않게 한다. 가격·상품·진행·저장 규칙은 변경하지 않았다.
- [공통 종이색 표면·선택·버튼](../../ios-pixel-boxing/PixelBoxingIOS/RivalMenuComponents.swift)은 명시적으로 선택하는 변형이다. 기존 어두운 화면의 기본값은 유지한다. 눌림·선택·패널 전환과 시스템 동작 줄이기는 기존 공통 헬퍼를 재사용하며, [한·영·일 준비 문구](../../ios-pixel-boxing/PixelBoxingIOS/Localization.swift)를 추가했다.

### 큰 글씨와 작은 가로 화면

- 최대 접근성 글씨에서는 한 열의 스크롤 목록을 사용하고, 복장·스타일 그림과 중복된 전체 선수 요약을 생략한다. 복장 탭의 선택 이름·착용/미리보기·해금 조건은 목록 앞에 둔다. 닫기·네 탭·하단 행동은 따로 남긴다.
- 긴 해금 설명이 선택 버튼 자체를 지나치게 키우지 않도록, 큰 글씨의 스토리 복장·외형·사우스포 설명을 해당 선택 버튼 바로 아래에 둔다. 조작 영역이나 글씨 크기를 줄여 해결하지 않는다.
- 큰 글씨에서는 중복된 스토리 분류 설명 문단을 생략하지만 분류 제목·구매 진입과 각 장비의 실제 이용권·승리·해금 조건은 유지한다. 원래 일반 크기 화면의 설명은 남긴다.
- [집중 UI 검사](../../ios-pixel-boxing/PixelBoxingIOSUITests/PixelBoxingIOSUITests.swift)는 카탈로그를 실제로 스크롤하고 선택 결과를 검사한다. 고정 조작부의 화면 안 배치·최소 높이와 선택한 복장/스토리 시작 복장의 요구 문장이 실제 스크롤 뷰포트 안에 완전히 들어오는지도 별도로 검사한다. 외형 목록은 동적 인덱스 대신 안정된 식별자로 선택한다.

### 보존 범위

- [독립 선수 미리보기 래퍼](../../ios-pixel-boxing/PixelBoxingIOS/Arena3DScene.swift)에 준비 화면용 배경과 머리 위 독립 식별 라벨 표시만 선택적으로 조정하는 훅을 추가했다. 기존 기본 호출에는 적용하지 않는다. 복장·벨트의 실제 글자까지 숨기지 않는다.
- 원래 미리보기 카메라 위치·40도 시야각·조명·가드 포즈·16초 회전과 동작 줄이기 정지 상태를 유지한다. 실제 게임 장면·복서 리그·메뉴 대기 모션을 교체하지 않았다.
- 라커룸 시작 시점의 별도 기준 사본과 대조해 경기장 소스에서 미리보기 래퍼 이전·이후 본문이 동일함을 확인했다. 전투·컨트롤러·스토리 진행·구매·포즈·복싱 모션·메뉴 디자인 소스 7개의 해시도 동일하다. 이전에 별도로 들어온 사우스포 모델 변경은 이 작업에서 수정하거나 되돌리지 않았다.

### 검증과 제한

- [집중 단위 검사](../../ios-pixel-boxing/PixelBoxingIOSTests/MainMenuPresentationTests.swift) 13개가 통과했다. 실제 장비 견본 15개가 번들에서 로드되고, 원래 미리보기 카메라·장비 설정을 재사용하는지도 검사한다. 서명된 iPhone SDK 앱·테스트 러너 빌드가 통과했다.
- **최종 넓은 iPhone 시뮬레이터 집중 검사 16개: 단위 13개 + UI 3개**, 실패 0개. 일반 크기 라커룸, 최대 글씨, 스토리 선택·준비 취소를 검사했으며 각 UI 메서드는 한·영·일을 모두 실행한다. **별도의 iPhone 12 mini 시뮬레이터 최대 글씨 UI 검사 1개도 세 언어에서 통과했다.** 스타일·잠긴 복장·기본 자세와 스토리 시작/챔피언 복장·선택 가능한 외형 6개·사우스포의 실제 선택 결과, 요구 문장 전체 노출과 고정 조작부를 검사했다.
- 실기기에서는 일반 크기의 한·영·일 스타일·복장·자세·스토리 상태와 준비 취소 검사 2개가 실제로 실행되어 통과했고, 라커룸 화면 9장을 캡처했다. 이후의 마지막 보정은 접근성 글씨 배치에 한정한다.
- 최초 큰 글씨 검사에서는 선택 설명의 위치·과도한 버튼 설명과 스토리 안내 문단 때문에 선택 접근 검사가 실패했다. 확장 외형 검사에서는 부분 노출 상태의 선택 결과도 실패해, 전체 노출 스크롤과 안정된 식별자로 선택 경로를 보완했다. 이를 일반 크기 화면의 실패나 테스트 시작 실패와 혼동하지 않는다. 확장 외형 검사는 실제 선택까지 검사하며 단순 존재 여부로 대체하지 않는다. 선택 요구 문장의 프레임 검사는 최종 성공 과정에서도 유지했다.
- **최종 최대 글씨의 실기기 확인은 미완료다.** 잠금 해제 후에도 Xcode가 자동화 모드를 켜는 단계에서 반복적으로 시간 초과되어 마지막 UI 검사는 실행되지 않았다. 정상 앱을 먼저 실행하고 미리 빌드한 러너로 순차 검사하는 방법도 실패했다. 이를 앱 UI 실패나 통과로 기록하지 않는다.
- 실기기 자동 터치·화면 캡처와 사람의 직접 터치·햅틱·플레이 체감은 구분한다. 실결제·복원·실제 서버 랭킹·장기 플레이 영향·전체 회귀 성공·배포를 새로 검증한 것은 아니다. 최종 서명 앱을 사용자 데이터를 지우지 않고 iPhone에 설치하고, 별도 언어·fixture 인자 없이 정상 실행했다. 최종 소형 시뮬레이터 캡처는 실제 기기 사진과 구분하며, 작업용 소형 시뮬레이터만 검사 후 정리했다.

### 다음 묶음

메인·스토리·라커룸의 실제 플레이 피드백을 받은 뒤 실전 HUD·조작부, 코너 및 결과 기록지 순서로 진행한다. 이 라커룸 작업에서 게임 장면·컷씬·맵·복서·복장 디자인을 새로 만들거나, 보류 중인 포스터를 통합하지 않았다.

## 14. 후속 네이티브 적용: 실전 HUD·버튼 외형, 기존 배치 유지

### 확정된 범위

- 사용자는 작은 화면·큰 글씨·VoiceOver·동작 줄이기 확인을 제외하고 나머지를 진행하도록 요청했다. 이번 검사는 기본 설정의 넓은 iPhone 시뮬레이터와 한·영·일 현지화, 일반 입력·경기 흐름 및 iPhone SDK 빌드에 한정한다. 기존 접근성·동작 줄이기 지원은 유지한다.
- 버튼의 디자인과 눌림 피드백은 바꿀 수 있지만 배치는 바꾸지 않는다는 후속 제한을 적용했다. 작업 중 시도했던 방어·백스텝 이동은 기준 사본의 배치로 되돌렸다.
- 왼쪽 3×3 패드의 위빙·전진 / 좌우 이동·가드 / 더킹·후퇴 배열과 오른쪽 상단 백스텝·하단 잽/크로스를 유지한다. 기존 크기·간격·안전 영역 여백과 자세에 따른 좌우 손 매핑도 유지한다.

### 실제 적용

- [실전 화면](../../ios-pixel-boxing/PixelBoxingIOS/GameView.swift)의 넓은 HUD 받침을 없애고 양측의 얇은 체력·스태미나 바와 중앙 시계에 각각 필요한 불투명 받침만 둔다. 상태 바는 기존 210pt 제한보다 넓게 사용하며, 설정 버튼을 옮기지 않고 HUD 자체의 여백으로 분리한다.
- 남은 경기 시간은 `00:45` 형태로 표시한다. 초의 올림 경계와 실제 경기 시간은 그대로이며, 중앙 KO 슬롯·공개/종료 시점·점수와 스토리의 카운트·코너 타이머·T.K.O. 조건은 유지한다. 카운터 문구는 더 작은 띠로 정리하며 나레이터 박스를 다시 넣지 않는다.
- 조작부는 무광 표면, 작은 모서리, 절제된 테두리와 옅은 청색/벽돌색 공격 버튼으로 바꾼다. 실시간 조작 버튼에 그라디언트를 넣지 않는다. 홀드·조합·잠김 표시와 기존 눌림 시점·축소 피드백을 유지한다.
- [공용 스타일](../../ios-pixel-boxing/PixelBoxingIOS/UIStyleKit.swift)과 버튼의 `onRing` 옵션은 실전 호출부에서만 적용한다. 공용 버튼을 쓰는 체육관의 기본 외형·동작은 유지한다.
- 캡처 확인 중 작은 글리프가 불분명한 경우를 발견해 조작부의 기존 글자체와 아이콘 굵기를 유지하고, 실제 이미지 픽셀 검사를 보완했다. 확대 확인에서 HUD의 체력·선수명·점수도 읽히는 것을 확인했다. 축소 미리보기만으로 글리프 누락이나 정상 표시를 단정하지 않는다.
- 공격은 기존 터치다운 단일 발동, 홀드 버튼은 기존 누름·해제·비활성화/이탈 정리를 그대로 사용한다. 전투·AI·진행·구매 수치를 이 UI 작업에서 변경하지 않았다.

### 검증과 제한

- **최종 집중 검사 13개: 단위 10개 + UI 3개, 실패 0개.** [단위 검사](../../ios-pixel-boxing/PixelBoxingIOSTests/CombatPresentationTests.swift)는 시계의 초 경계·KO 슬롯, 현재 선수 스타일에서 홀드 중복 호출·해제, 원래 버튼 크기와 입력 조합을 확인한다.
- [세 언어 기본 설정 UI 검사](../../ios-pixel-boxing/PixelBoxingIOSUITests/PixelBoxingIOSUITests.swift)는 3×3 버튼의 58×54pt 크기·행/열 정렬·5pt 간격과 공격 버튼의 94×76pt 크기·7pt 간격, 상단 백스텝의 196×44pt 크기·6pt 수직 간격을 실제 좌표로 확인한다. 방향·가드 아이콘의 중앙 28×28pt 영역에 밝은 픽셀이 20개를 초과하는지도 검사해, 버튼 존재 여부만으로 표시 성공을 판단하지 않는다.
- 나레이터 부재, 시계 중앙 정렬, 설정 버튼과 HUD의 분리, 원래 메인 입장 연출을 거친 경기 진입, 공격 홀드로 KO → 결과 → 다음 라운드, 가드·백스텝 접근을 확인했다. 사람의 실제 터치감·햅틱·장기 플레이 영향이나 전체 회귀 성공을 확인한 것은 아니다.
- 초기 빌드는 확장된 SwiftUI 표현식의 타입 검사 시간 초과로 실패해 색·모서리 값을 명시적인 타입으로 나눴다. 초기 넓은 HUD의 설정 버튼 여백 검사도 실패해 HUD 여백만 보정했다. 중간 통과 이후에도 캡처를 확인하고 글리프 픽셀 검사를 추가해 최종 검사를 다시 실행했다.
- 먼저 선택한 기존 위빙 검사는 기대 스태미나 `88`과 실제 `91`이 맞지 않았고, 기존 선택적 인트로 건너뛰기 검사는 자동 입장이 끝난 뒤 사라진 버튼을 탭하려다 실패했다. 해당 기존 검사·전투 수치·입장 연출을 이 작업에서 수정하지 않았다. 현재 스타일의 중복 홀드 비용·해제와 실제 자동 입장 경로를 별도로 검사했으며, 앞선 실패를 통과로 바꿔 기록하거나 전체 기존 테스트가 성공했다고 주장하지 않는다.
- 서명된 iPhone SDK 빌드가 통과했고 **13:00 KST에 최종 수정 앱을 실제 iPhone에 설치했다.** 사용자 데이터는 지우지 않았다. 마지막 정상 실행 요청은 기기 잠금으로 차단됐다. 이전 중간 빌드는 12:46 KST에 별도 언어·fixture 인자 없이 정상 실행했지만 이를 최종 수정본의 실행 확인으로 대체하지 않는다. 마지막 수정본의 실기기 화면·직접 터치·햅틱은 미확인이다.
- 기준 사본과 대조해 버튼 배치·홀드/공격 제스처 본문, 기존 라커룸과 스토리 시계 밖의 선택·컷씬·결과 본문이 유지됨을 확인했다. 보호 대상 소스 중 전투·컨트롤러·입력·AI·모션·스토리·구매·메뉴·맵·입장 연출 등 **12개의 최종 해시는 동일하다.**
- **동시 작업 구분:** [경기장 소스](../../ios-pixel-boxing/PixelBoxingIOS/Arena3DScene.swift)에는 12:38에 별도의 사우스포 눈 메시·재질 변경이 들어와 최종 해시가 실전 UI 시작 기준과 다르다. 이 HUD 작업은 해당 모델 변경을 작성하거나 되돌리지 않았다. 따라서 현재 작업 트리 전체의 캐릭터 소스가 시작 시점과 동일하다는 보장은 하지 않는다.

### 다음 묶음

당시 실전 묶음에서는 코너·결과 레이아웃을 함께 교체하지 않았다. 이후 사용자가 남은 부분 전체의 완료를 요청해 아래 마지막 묶음까지 적용했다. 전투 버튼 배치 유지와 네 가지 검사 제외는 그대로 따른다.

## 15. 잔여 네이티브 적용 완료: 코너·결과와 보조 화면

### 확정된 범위

- 사용자의 남은 작업 전체 완료 요청에 따라 코너·결과, 설정·새 경기 확인·코너 노트·랭킹·스토리 이용권 안내와 체육관 헤더를 하나의 묶음으로 마무리했다.
- 원래 전투 버튼 배치·크기·간격과 터치다운·홀드·해제, 게임 장면·모델·맵·복장·카메라·컷씬·전투·AI·진행·구매 규칙은 변경하지 않는다.
- 작은 화면·큰 글씨·VoiceOver·동작 줄이기 검사는 이번 묶음에서도 실행하지 않았다. 지원 코드와 기존 동작을 제거하지 않았다.

### 실제 적용

- [공용 기록 표](../../ios-pixel-boxing/PixelBoxingIOS/RivalMenuComponents.swift)는 실제 `CombatSnapshot`의 양측 회피 성공·주요 공격을 사용한다. 공격이 없으면 기존의 `없음` 번역을 표시하고, 실제 코너 보고가 없으면 분석 문구를 만들어 넣지 않는다.
- [RIVAL 라운드 결과와 일시 정지](../../ios-pixel-boxing/PixelBoxingIOS/GameView.swift)를 따뜻한 종이색 표면·짙은 글자·절제된 코너 색으로 교체했다. 실제 승패·점수·결정타와 기존 결과 공개·다음 라운드 활성화 시점은 유지한다.
- [스토리 코너·결과](../../ios-pixel-boxing/PixelBoxingIOS/StoryViews.swift)에도 동일한 실제 기록을 전달한다. 결과의 회피·공격은 명시된 마지막 라운드의 기록이며 전체 경기 합계로 표현하지 않는다. 기존 채점표·보상 조건·카운트·코너 대기·재도전·상대 목록·다음 이야기 콜백은 유지한다.
- 실제 캡처에서 기록 표가 스크롤 아래로 잘리는 것을 발견해 코너 헤더를 압축하고 기록 영역을 넓혔다. 결과에서도 마지막 라운드 기록을 채점표보다 먼저 배치한다. 핵심 회피·공격 행은 처음 열린 화면에서 보이며, 긴 보고와 부가 채점표는 기존 스크롤로 읽는다. 전투 조작부의 배치를 바꾼 것은 아니다.
- 설정과 새 경기 확인은 라커룸과 같은 종이색 표면·선택 표시를 사용한다. 소리·햅틱은 실제 켜짐 상태를 선택 상태에도 연결하며, 기존 토글·언어·취소·초기화 콜백은 유지한다.
- [코너 노트](../../ios-pixel-boxing/PixelBoxingIOS/MainMenuView.swift)는 반복 카드 대신 행과 구분선으로 정리하고 `상대가 읽은 버릇`으로 표현한다. 공격 이력이 없어도 기본 잽을 반복 습관처럼 보여주던 행은 제외했다. 실제 RIVAL 읽기와 라운드 기록은 유지하며, 스냅샷·습관 분석 모델은 변경하지 않았다.
- [랭킹](../../ios-pixel-boxing/PixelBoxingIOS/LeaderboardView.swift)과 [스토리 안내](../../ios-pixel-boxing/PixelBoxingIOS/StoryPurchaseView.swift)도 같은 기록·준비 공간의 표면으로 맞춘다. 실제 로그인·로딩·오류·빈 순위, 가격·이용권·비활성·구매·복원과 보상 배열은 그대로 사용한다. 가짜 순위·가격·구매 완료 상태를 넣지 않았다.
- [체육관](../../ios-pixel-boxing/PixelBoxingIOS/PracticeView.swift)은 헤더·뒤로가기와 UI 배경의 외형을 연결한다. 기존 조작 버튼·연습 장면·시간 기록·입력과 해제 수명 주기는 유지한다.

## 16. 후속 요청: 실전 해설 복구

- 사용자가 인게임 해설을 복구하되 캐릭터를 가리지 않도록 배치해 달라고 요청했다. 14절의 해설 비노출 기록은 당시 상태이며 현재 구현은 이 후속 요청을 따른다.
- [실전 해설](../../ios-pixel-boxing/PixelBoxingIOS/GameView.swift)은 기존 `CombatSnapshot.message`를 사용한다. 일반 경기 상단 80pt·스토리 90pt부터, 최대 너비 500pt·높이 20pt의 한 줄과 작은 무광 배경으로 배치한다. 상단 안전 영역이 더 크면 기존 안전 영역 여백을 따른다.
- 별도 시그니처·카운터와 같은 공간을 번갈아 사용한다. 카운터 표시가 우선하며 두 문구를 겹쳐 전환하지 않는다. 해설은 터치를 가로채지 않는다.
- 인트로·스토리 연출·일시 정지·설정·KO·코너·결과에서는 해설을 숨긴다. KO 시계와 기존 라운드 공개·입력·진행은 변경하지 않는다.
- 기존 카운터 문구의 실제 보너스·피해 숫자도 표시될 수 있다. 일반 타격 피해 숫자나 새 음성 합성 기능을 추가하지 않았다.
- 전투 버튼의 위치·크기·간격·동작과 게임 장면·모델·맵·복장·카메라·전투·AI는 그대로 유지한다. 작은 화면·큰 글씨·VoiceOver·동작 줄이기 검사는 계속 제외한다.

### 검증과 제한

- **최종 집중 검사 8개, 단위 5개 + 기본 설정 UI 3개가 한 실행에서 모두 통과했다.** 최종 서명된 iPhone SDK 빌드도 통과했다. 전체 기존 테스트 클래스나 제외된 네 가지 검사는 실행하지 않았다.
- 실제 보이는 양측 캐릭터 메시를 기존 카메라로 투영한다. 근·원거리의 정지와 8개 공격 자세에서 일반·스토리 해설 영역이 캐릭터의 투영 경계와 **8pt 여유**를 두고 겹치지 않는지 검사했다. 카메라·장면·모델을 검사에 맞춰 바꾸지 않았다. 모든 맵·외형·연속 움직임이나 실기기 플레이 전체를 검증한 것은 아니다.
- 첫 단위 검사에서는 이름표와 보이지 않는 요소까지 포함한 전체 노드 경계를 사용해 과도한 경계가 만들어졌다. 실제 보이는 캐릭터 메시로 바꾼 후 스토리의 최초 28pt 높이 영역이 머리 쪽 여유를 침범하는 것을 확인해 **20pt 높이·상단 90pt**로 조정했다. 실패를 단순히 통과로 바꾸거나 여유 기준을 낮추지 않았다.
- 단위 렌더는 한·영·일 실제 시작/잽 해설이 한 줄에 들어가는지, 카운터가 해설을 대체하고 KO에서 모두 비워지는지 확인했다. 기존 KO 시계·우선순위·원래 버튼 크기 검사도 통과했다.
- UI는 한·영·일 해설의 실제 표시·잽 이후 갱신·상단 좌표, 원래 버튼 좌표·아이콘 픽셀과 설정 왕복·KO·다음 라운드를 확인했다. 스토리 코너·결과에서는 해설을 숨기며 재도전 인트로에서도 숨긴 뒤 기존 건너뛰기 버튼으로 경기에 돌아오면 복구되는지 검사했다. 최초 재도전 검사는 인트로 뒤의 잽 버튼 존재만으로 경기 재개를 판단해 실패했으며, 실제 인트로/경기 전환을 검사하도록 수정했다. 컷씬 시간이나 입력 동작은 바꾸지 않았다.
- **최종 앱은 14:26 KST에 실제 iPhone에 설치했다. 실행 요청은 기기 잠금으로 차단됐다.** 사용자 데이터를 지우지 않았으며 잠금을 우회하지 않았다. 이전 13:55 정상 실행 기록은 해설 복구 이전 앱의 기록이고, 수정본의 실기기 화면·터치감·햅틱·플레이 체감은 직접 관찰하지 못했다.
- 이번 요청 직전 기준과 비교한 전투·입력·AI·모션·장면·스토리·구매·입장 소스 **11개의 해시는 동일하다.** 원래 전투 조작/일시 정지/결과 본문과 홀드·공격 제스처, 라커룸 구간도 그대로다. 기존 동시 모델 변경을 작성하거나 되돌리지 않았다.
- 최종 실제 경기 해설 캡처 **4장**을 기존 세 언어 갤러리·오프라인 패키지에 추가했다. 기존 21장과 합쳐 네이티브 캡처는 25장이며 독립 시안의 예시 데이터와 구분한다.

## 17. 후속 요청: 경기 시야와 메인 전신 가림 줄이기

- 사용자가 기존 위치 유지 조건을 변경해 좌우 전투 버튼 묶음을 더 양쪽으로 벌리도록 요청했다. 일반·스토리 공용 조작부에서 이미 안전 영역 안에 있는 컨테이너의 중복 좌우 안전 영역 여백을 제거하고 4pt 여백만 유지한다. 각 묶음의 버튼 순서·크기·내부 간격과 입력 동작은 변경하지 않는다.
- 메인 경기 시작 행과 하단 탐색 행의 넓은 배경 바를 제거했다. 경기 시작·스토리·라커룸·체육관 버튼과 기존 라이브 복서의 모델·카메라·모션은 유지한다.
- 사용자가 직접 검증하겠다고 요청해 이번 수정은 빌드·테스트·캡처·기기 설치를 실행하지 않았다. 16절의 검증·설치·갤러리는 이번 위치/배경 변경 전의 기록이며 새 화면의 검증 결과로 표현하지 않는다.

## 18. 후속 요청: 메인 하단 버튼별 가독성

- 전체 하단 바를 제거한 뒤 글자가 잘 보이지 않는다는 사용자 피드백에 따라 RIVAL 선택 표시·스토리·라커룸·체육관을 각각 작은 무광 단색 박스로 표시한다. 얇은 테두리와 기존 밝은 글자를 사용하며 RIVAL의 선택 표시는 유지한다.
- 하단 전체 배경 바는 복구하지 않는다. 기존 경기 시작 버튼, 하단 버튼의 위치·크기·간격·동작과 캐릭터·카메라·모션은 변경하지 않는다.
- 사용자 요청에 따라 빌드·테스트·캡처·기기 설치 없이 소스만 수정했다. 실제 가독성과 전신 가림 개선 여부는 사용자 확인 전이며 이전 캡처를 이번 수정의 검증으로 표현하지 않는다.

## 19. 승인 브랜딩의 앱 적용

2026-11-08 사용자가 아이콘 B안과 로고·시작 화면·포스터의 앱 내부 적용을 승인했다.
선택형 체육관 연습 안내도 포함한다. App Store 준비 작업은 별도 요청 전까지 중단 상태다.

- **아이콘:** 승인된 B안 원본을 iOS 앱 아이콘에 적용했다. 불투명 1024×1024 정사각형이며 둥근 마스크를 원본에 넣지 않는다.
- **공통 로고:** 독립 기하학 워드마크의 같은 외곽선을 메인·스토리·체육관·이용권 아트에 재사용한다. 현재 앱은 배경에 맞춰 밝은 색·적색 계열을 사용한다. 먹색은 시안 원본의 색상 옵션이며 현재 화면에 별도로 적용한 색은 아니다. 본문과 버튼의 현재 서체는 유지한다.
- **시작 화면:** 정적 [LaunchScreen.storyboard](../../ios-pixel-boxing/PixelBoxingIOS/LaunchScreen.storyboard)와 기존 복싱 오프닝에서 너비 148pt·상단 32pt의 로고를 이어 표시한다. 기존 오프닝의 안무·카메라와 정상 설정의 1.6초 연출 구간은 유지하며 가짜 진행률·새 대기 구간·새 컷씬을 추가하지 않는다.
- **메인:** 상단 워드마크만 교체한다. 라이브 RIVAL과 기존 카메라, 제거한 넓은 하단 바, 개별 탐색 버튼 표면과 현재 버튼 위치를 유지한다. 캐릭터 전신이 모든 화면에서 완전히 보인다는 주장은 하지 않는다.
- **스토리:** 기존 링 배경의 노출과 실제 일곱 상대의 단체 구도를 시안에 맞춘다. 이미지에는 이름·진행·선택·잠금 상태를 합성하지 않으며 실제 로컬라이즈된 UI와 저장된 진행을 사용한다. 선수 선택 시 개별 초상으로 전환하는 동작, 아래 선수 목록·위쪽 컷씬 다시보기·경기 준비 위치와 진행 규칙을 유지한다.

## 26. 개발용 시작 설정의 자세 덮어쓰기 제거

- 시작 시 강제 장착을 제거하고 [진행 저장소](../../ios-pixel-boxing/PixelBoxingIOS/StoryMode.swift)의 개발용 저장소 진입점으로 기존 선택을 그대로 읽는다. 임시 콘텐츠 해금, 독립 저장 공간 `rival.story.preview.v1`과 일반/스토리 컨트롤러의 장비·자세 전달 경로는 유지한다. 외형과 자세는 별개 선택이며 저장된 외형을 사우스포로 다시 고정하지 않는다.
- 기존 선택을 오소독스로 일괄 초기화하거나 진행 데이터를 지우지 않는다. 사우스포를 실제로 선택한 사용자도 재실행과 새 경기에서 그 선택을 유지해야 한다. 새 저장소의 기본 자세는 기존 오소독스를 유지한다.
- 별도 기존 동작 두 가지는 변경하지 않는다. 진행 중 경기에서는 라커룸 자세 선택이 미리보기만 적용되고 실제 장착은 경기 전/종료 후에 가능하다. 스토리 이어하기는 전역의 다음 경기 선택과 별개로 체크포인트에 저장된 선수 자세를 복원한다. 저장된 경기 자세·규칙·판정·공격 모션을 덮어쓰는 변경은 하지 않았다.
- 서명된 iPhone SDK 테스트 빌드와 실기기 집중 단위 2개가 통과했다. 사우스포 강제값에서 오소독스/사우스포·다른 외형을 선택한 뒤 개발용 저장소를 다시 열어 선택이 유지되는지, RIVAL·새 스토리 경기와 인트로 종료 뒤 실제 엔진/컨트롤러 자세가 같은지 확인했다.
- 이어하기 회귀 검사는 사우스포 체크포인트와 다음 경기의 오소독스 선택을 분리해, 이어하기의 사우스포 복원이 다음 경기 선택을 덮어쓰지 않음을 확인한다. 테스트는 고유한 임시 저장 영역만 사용하고 사용자 진행 데이터를 수정하지 않는다.
- 02:16 KST에 기존 데이터를 지우지 않고 iPhone에 설치·정상 실행했다. 사람이 실제 경기의 자세·손 방향·펀치 모션을 관찰한 검증은 아니다. 별도 UI 검사·전체 회귀·Release 실행과 App Store 배포는 수행하지 않았다.

## 27. 1.3 배포 준비 재개

2026-11-09 사용자가 버전을 올리고 승인된 포스터·홍보 문구·심사 메타데이터를 준비하도록 요청했다.
앞선 절의 배포 중단·음원 권한 미확인은 당시 상태이며 이번 요청으로 준비를 재개했다.

- 실제 프로젝트와 명세를 `1.3(7)`로 올리고 서명된 Release 아카이브·App Store IPA를 생성·검증·업로드했다.

  컨트롤러/엔진이 오소독스로 시작함을 확인했다. 저장된 사용자 선택·체크포인트 자세는 변경하지 않았다.
- 최종 실제 Release UI 캡처는 한·영·일을 두 기기에서 각각 실행해 총 6회 통과·실패 0, 원본 42장이다.

  초기 3D 프레임·화면 페이드가 끝난 뒤 촬영했다. 이 수정은 UI-test 코드에만 있으며 배포 앱 동작을 바꾸지 않는다.
